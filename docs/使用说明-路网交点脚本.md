# 路网交点使用说明：从一堆路，到可用的路口节点

> 一句话：把任意一份合规的路网 GeoJSON 丢进来，几条命令就能算出所有路口、列出问题，不用任何大模型参与。

---

## 一、五个部分

| 名称                      | 作用                                             | 是否会改数据                   |
| ------------------------- | ------------------------------------------------ | ------------------------------ |
| `merge-roads.mjs`         | 把新路并入已有路网，先校验再追加                 | 只有加 `--write` 才改          |
| `build-intersections.mjs` | 算交点、建交点文件、把交点顶点插进路网           | 只有加 `--write` 才改          |
| `junction-diagnose.mjs`   | 诊断：A 接近交点 / B 欠伸 / C 过冲；可顺带修 B/C | 默认只读，`--fix --write` 才改 |
| `junction-cases.html`     | 上面两个脚本结果的可视化裁定页                   | 不改                           |
| `boundary-compare.html`   | 两套区界叠加比对                                 | 不改                           |

所有脚本默认 **dry-run**，只打印结果。只有明确写上 `--write` 才会落盘。

---

## 二、最常见情况：往现有路网里加几条新路

```bash
# 1) 先看看新路能不能用（只校验，不写）
node scripts/merge-roads.mjs --add 新路.geojson

# 2) 没问题就并入
node scripts/merge-roads.mjs --add 新路.geojson --write

# 3) 重算交点（把交点顶点写进路网 + 生成交点文件）
node scripts/build-intersections.mjs --write

# 4) 出诊断报告
node scripts/junction-diagnose.mjs

# 5) 有 B/C 缺陷就修（先看修复计划，确认后再落盘）
node scripts/junction-diagnose.mjs --fix all
node scripts/junction-diagnose.mjs --fix all --write

# 6) 重算交点，把修出来的路口补成节点
node scripts/build-intersections.mjs --write
```

新路的要求只有四条：

1. 几何是 `LineString` 或 `MultiLineString`
2. `properties.roadId` 必填，且不能和已有的重复
3. `properties.name` 必填
4. 每条线至少 2 个顶点

任何一条不满足，`merge-roads` 会整体拒绝，不会写进去半套数据。

## 三、从空路网开始

```bash
node scripts/merge-roads.mjs --base none --add 新路.geojson \
  --out D:/x/roads.geojson --write

node scripts/build-intersections.mjs --roads D:/x/roads.geojson \
  --out D:/x/intersections.geojson --report D:/x/reports --write

node scripts/junction-diagnose.mjs --roads D:/x/roads.geojson \
  --nodes D:/x/intersections.geojson --out D:/x/reports
```

如果连交点文件都没有，诊断也能跑，A 会自动跳过：

```bash
node scripts/junction-diagnose.mjs --roads D:/x/roads.geojson --nodes none
```

## 四、报告怎么看：A 到 E 五类

打开 `http://localhost:<端口>/reports/junction-cases.html`（端口以 `npm run dev` 实际输出为准）。

| 分类 | 名字     | 意思                                                         | 该怎么办                                                |
| ---- | -------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| A    | 接近交点 | 几个节点挤在 30 m 内                                         | 选一个基准点（当前只输出建议 `anchorReason`，尚未写回） |
| B    | 欠伸     | 路已经画到路口附近，但没接上（缺口 3–30 m，3–15 m 可自动修） | 端点延长到目标线（`--fix under`）                       |
| C    | 过冲     | 已经接上了，但端点又多长一小截（0.3–15 m）                   | 剪掉多余尾巴（`--fix over`）                            |
| D    | 共线重叠 | 两条线贴在一起走了一段                                       | 需人工去重（脚本只报告，不自动删）                      |
| E    | 无交点   | 整条路没和任何线相交                                         | 检查是否漏画连接                                        |

页面操作：

- 顶部按钮筛选某一类
- 点条目自动定位、高亮
- 详情区显示距离、角度、建议坐标

## 五、页面可以换成别的数据

三个地址参数，不传就是本项目默认值：

```
/reports/junction-cases.html?roads=/data/roads.geojson&report=/reports/junctions/latest.json&ix=/reports/intersections/latest.json
```

- `roads`：路网文件
- `report`：诊断报告（A/B/C 来源）
- `ix`：交点构建报告（D/E 来源）

## 六、常用参数

### build-intersections

| 参数                             | 默认       | 含义                                  |
| -------------------------------- | ---------- | ------------------------------------- |
| `--tol`                          | 3          | 端点距目标线 ≤ 该值（米）算接上       |
| `--candidate`                    | 10         | 两线最近距离 ≤ 该值（米）记为候选缺口 |
| `--cluster`                      | 1          | 交点聚类半径（米）                    |
| `--roads` / `--out` / `--report` | 项目内路径 | 输入、交点文件、报告目录              |
| `--write`                        | 关         | 落盘                                  |

### junction-diagnose

| 参数                            | 默认       | 含义                                                       |
| ------------------------------- | ---------- | ---------------------------------------------------------- |
| `--near`                        | 30         | A 类近邻半径（米）                                         |
| `--under-min` / `--under-max`   | 3 / 15     | B 类可自动修的缺口范围（米）                               |
| `--under-warn`                  | 30         | B 类仅告警的上限（米）                                     |
| `--pointing-max`                | 30         | 端点指向允许偏差（度）                                     |
| `--min-angle`                   | 30         | 线与目标线的最小夹角（度）                                 |
| `--over-min` / `--over-max`     | 0.3 / 15   | C 类尾巴长度范围（米）                                     |
| `--fix`                         | 关         | `under` / `over` / `all`，生成 B/C 修复计划                |
| `--write`                       | 关         | 配合 `--fix` 落盘（改 `--roads` 指向的文件）               |
| `--pair`                        | 关         | 只追踪一对线，如 `--pair 花园路×灵山大街`（也接受 roadId） |
| `--roads` / `--nodes` / `--out` | 项目内路径 | 输入输出；`--nodes none` 跳过 A                            |

> `--write` 只能配合 `--fix` 使用；`--fix` 与 `--pair` 互斥，同时传会直接报错退出。
> 修完后记得再跑一次 `build-intersections.mjs --write`，把新路口补成节点。

## 七、常见报错

| 报错                                                  | 原因                     | 处理                                            |
| ----------------------------------------------------- | ------------------------ | ----------------------------------------------- |
| `❌ 缺少 --add`                                       | 没有指定新路文件         | 补 `--add 路径`                                 |
| `与基线已有 roadId 重复`                              | 新路 ID 撞了             | 改 ID 或先删除旧要素                            |
| `缺少 properties.roadId`                              | 导入数据没带 ID          | 先在源数据补 ID                                 |
| `几何类型 Polygon，只接受…`                           | 混进了面要素             | 只保留线要素                                    |
| `❌ 路网文件 不存在`                                  | 路径写错或用了相对路径   | 用绝对路径或确认当前目录                        |
| `❌ 交点文件 不存在`                                  | `--nodes` 指向的文件缺失 | 先跑 `build-intersections`，或传 `--nodes none` |
| `❌ --base none 时必须用 --out 指定输出路径`          | 空网起步没给输出位置     | 补 `--out 路径`                                 |
| `❌ 输入不是 FeatureCollection（缺少 features 数组）` | 文件不是标准 GeoJSON     | 检查顶层 `type` 与 `features`                   |
| `❌ --tol 需要数字，当前: …`                          | 数值参数后面不是数字     | 改成纯数字（不要带单位）                        |
| `❌ 路网文件里没有可用的线要素`                       | 全是面要素或空几何       | 只保留 `LineString` / `MultiLineString`         |

---

## 八、两条硬规矩

1. **已发布的版本不能原地改**。改数据要重新生成发布包，并让 `data/current.json` 指向新版本。
2. **先 dry-run，确认数字合理再 `--write`**。不加 `--fix` 时诊断脚本只读，可以放心反复跑。
