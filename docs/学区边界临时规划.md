# 学区边界修复与辅助标注临时规划

> 状态：待实施，不代表现有能力。
> 定位：对 [完善规划.md](../完善规划.md) 中 P0-6 的阶段性细化，优先级不低于部署。
> 本次只形成规划，不修改业务代码、安装依赖或改动学区数据。

## 一、目标与现状

学区边界是地址查询结果的基础。当前最需要解决的不是继续增加展示功能，而是让边界能够可靠地制作、检查、修复和持续更新。

当前工作副本包含 14 个学区（12 个初中、2 个小学），均标注为人工近似边界。现有校验主要检查字段、引用关系、坐标与环闭合，尚未形成完整的几何关系检查和修复流程。

本阶段围绕两条主线推进：

1. **学区修复脚本化**：自动定位问题，把已经人工确认的修复规则变成可重复执行的操作，减少反复拖点和人工比对。
2. **学区标注辅助自动化**：结合网页端 AI、现成地图编辑工具和自动校验，减少读文件、描边和复核中的机械劳动。

原则：**程序负责计算和重复操作，人工负责解释政策、确认边界归属。**

## 二、当前学区新建与修复工作流（人工 + 大模型辅助）

在提出改进方案之前，先记录目前的实际做法。这套流程没有书面文档，主要靠个人经验与对话式操作，因此也无法交接和复核。

### 1. 完整流程（三步）

**第一步：查文件、理解范围。**
从教育主管部门公开的招生文件或四至范围统计表中，逐条读取该学区边界的文字描述，例如：

> 东界：致富路，荣军医院东路；西界：佳苑路，长城路；南界：灵山大街；北界：铁路。

这一步由人工完成两件事：把方位词与参照物对应到真实地理位置，并判断文字描述的是哪一段范围。遇到参照物是道路以外的地物（如铁路）、同一条路分成多段、或存在排除说明时，需要额外推理。

**第二步：在地图上标点。**
根据上一步的理解，在地图上逐个顶点描出该学区的边界（Polygon）。项目内没有固定的绘图工具约定，描点也没有吸附能力。

**第三步：大模型判断 + 人工评判的迭代核对。**
绘制完成后，把待检查的数据上传给大模型工具，由它判断是否与已有学区存在重叠；人工再评判这一判断和修改结果，给出反馈。若发现修改后某处仍然重叠，则打回重新修改，如此往复，直到人工认可为止。确认无明显问题后，写入 `data/zones.geojson`，同时手填业务属性：

| 字段                              | 作用                                                                   |
| --------------------------------- | ---------------------------------------------------------------------- |
| `boundaryText`                    | 原始四至文字，保留来源描述                                             |
| `sourceName` / `sourceUrl`        | 依据的文件名称与链接                                                   |
| `year` / `verifiedDate`           | 适用年份与核对日期                                                     |
| `dataStatus` / `geometryAccuracy` | 数据状态与几何精度（现有条目均为 `estimated` / `manualApproximation`） |
| `note`                            | 精度与使用限制说明                                                     |

即：**判断这一步已经有大模型参与，不是纯人工目视；但结论的确定权仍在人工。**

### 2. 问题所在

- **边界理解依赖个人判断，且不落盘。** 哪段路对应哪条界、为什么这样取舍，只存在于执行者脑中；`boundaryText` 保留了原文，但没有记录从文字到顶点之间的判断过程。
- **相邻学区要各画一次。** 共用边界的两侧分别描线，两次描线必然产生错位，形成窄长重叠或缝隙。
- **核对结论不可重放。** 判断虽然已经交给大模型，但结论停留在当次对话里，没有落进项目文件；换人或换一次对话，结论可能不同，也无法回答"当时凭什么判定不重叠"。
- **大模型判断几何重叠并不可靠，人工成本随规模上升。** 窄长重叠、完全包含、细小缝隙容易被漏看，也可能给出看似确定却缺乏依据的结论；因此需要人工逐轮评判、反复打回重改，学区越多这一成本越高。
- **项目内仍然没有自动检查。** 现有校验只覆盖字段、引用关系、坐标与环闭合；几何关系判断既不在仓库里，也不能在提交或发布时被重复执行。
- **结果不可复现。** 同一份文件换人再画，会得到不同的边界，且无法判断哪个更接近官方范围。

这两条主线分别针对上述环节：**修复脚本化**替代第三步的"大模型判断 + 人工反馈"迭代，把结论固化为可重复执行的检查；**标注辅助自动化**降低第一步和第二步的机械劳动。

## 三、主线一：学区修复脚本化（优先落地）

### 1. 先检查，形成现状问题清单

规划新增独立检查入口，复用已有的数据校验能力，并补充：

- 几何有效性：自相交、退化区域、内外环异常等；
- 同学段、同一适用年份学区之间的面积重叠，包括包含关系与重复区域；
- 对已经确认应当共边的学区，检查边界是否错位；
- 在有明确完整覆盖范围的前提下，检查该范围内的疑似遗漏。

检查输出不仅要列出学区名称和问题类型，还应提供面积、位置和可在地图工具中查看的问题图层，避免只看到报错却找不到位置。

**判定边界：**

- 小学与初中之间重叠正常，不作为冲突；不同年份分别检查。
- 同学段重叠先列为待核实问题，不直接认定违规；共同招生等政策例外须有依据。
- 共享一条边不等于面积重叠。
- 当前数据覆盖不完整，不能将所有空白区域视为漏划。没有覆盖范围或明确邻接关系时，只能提供疑似问题提示，不能作出确定结论。
- 首版保留原始相交结果及面积，不把统一收缩多边形作为前置条件，以免掩盖狭窄重叠或破坏小区域。容差处理须经样本验证后再决定。

### 2. 人工确认问题及处理规则

将清单中的问题分为三类：

| 类型                     | 处理方式                                                 |
| ------------------------ | -------------------------------------------------------- |
| 格式或几何构造问题       | 评估能否安全修复；不得把明显改变范围的修复当作纯格式整理 |
| 边界错位、重叠或疑似漏划 | 对照原始文件和地图，由人工确认正确边界与归属             |
| 政策例外或资料不足       | 有依据的例外单独记录；无法确认的继续保留不确定状态       |

每个需要修改的问题至少记录：涉及学区、原始依据、处理决定、需要改变的边界及确认状态。不能仅凭“改完没有重叠”认定修复正确。

### 3. 将确认后的修复动作脚本化

规划建立与检查分开的修复入口，按明确的修复记录生成候选数据。例如：

- 两个相邻学区复用同一段已经确认的边界，避免分别描线造成错位；
- 对已确认归属的重叠区域，按指定规则调整对应学区；
- 对已确认的局部边界，用核实后的边界替换，而不是反复手工修改坐标。

**安全约束：**

- 默认只预览或输出候选文件，不覆盖工作副本；
- 没有明确归属依据，不自动裁剪、填缝或按学校远近分配；
- 输出修改前后对比，包括涉及学区、面积变化和变化区域；
- 保留学区 ID、学校关联、政策来源等业务属性；
- 重复执行不应不断改变结果；不适用或无法处理时明确报错；
- 人工核对候选结果后，才允许更新工作副本。

### 4. 从报告逐步转为发布门禁

先运行报告模式，查明历史问题和数值噪声；再用已核实样本确定容差、修复问题并登记政策例外。最终将明确的错误接入日常检查和发布检查。

报告模式不阻止尚待核实的业务问题，但文件损坏、计算失败等执行错误不能静默通过。不得单纯调大阈值掩盖已有问题。

## 四、主线二：学区标注辅助自动化（先借工具，不急于自建）

### 1. 网页端 AI 辅助整理文件

让 AI 协助从官方文件中提取：学校名称、学段、年份、四至描述、涉及道路与小区、特殊招生说明，并保留原文位置及来源。

人工重点复核同名道路、分段边界、排除条款和特殊情形。AI 输出作为整理草稿，不直接成为政策结论，更不能让 AI 凭文字猜坐标。

### 2. 优先试用 QGIS 完成辅助绘图

QGIS 是现成的桌面地图编辑工具，本阶段先用少量学区试用，确认是否适合团队操作，不预设所有成员必须立即切换。

重点验证：

- 导入现有学区后，按学段和年份分组编辑；
- 在具备访问条件、坐标约定明确的底图上核对位置；
- 吸附到相邻学区的顶点和边界，减少重复描线；
- 使用拓扑编辑工具辅助维护共边，避免只修改一侧；
- 导出后保持属性、坐标顺序及项目使用的坐标约定不变。

吸附到已有学区不等于吸附到道路。沿道路自动描边需要额外的可靠矢量数据，不能从栅格底图直接获得，本期不作承诺。

### 3. 绘制后立即自动检查

形成固定流程：

**原始文件 → AI 整理草稿 → 人工确认 → 辅助绘图 → 脚本检查 → 人工复核变化 → 数据发布。**

标注以 GeoJSON 为最终交付数据；QGIS 工程只保存图层配置等编辑环境，不再维护一份独立权威边界。优先使用共享边界或复用已确认线段，避免每个学区从零描绘。

### 4. 内置网页编辑器作为后续候选

只有在试用后仍存在明确效率瓶颈时，再评估轻量网页编辑器。最小范围是：加载已有学区、编辑顶点、查看检查结果、导出候选数据。

本期不承诺道路自动吸附、实时缝隙分析、账号或在线发布后台。编辑器可以独立于管理后台建设，不以新增数据库或账号体系为前提；实际需要时再复用脚本的检测逻辑，不提前为未实现的功能增加复杂结构。

## 五、实施顺序与阶段交付

| 阶段                 | 主要工作                                                           | 交付与进入下一阶段的条件                       |
| -------------------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| 第一阶段：摸清问题   | 几何检查、重叠分析、输出可定位的问题图层                           | 现状清单；明确哪些可以判断、哪些缺少资料       |
| 第二阶段：跑通小闭环 | 选一组有代表性的问题，核实依据并脚本生成修复候选；同时试用辅助绘图 | 可重复执行的修复样例、前后对比及人工复核记录   |
| 第三阶段：逐步推广   | 按确认规则处理其余问题，固化 AI 整理与绘图步骤                     | 已处理或有明确状态的问题清单、可交接的操作流程 |
| 第四阶段：纳入发布   | 确定检查阈值、政策例外和阻断规则                                   | 日常及发布检查接入；检查失败有明确处理方式     |

**优先保证第一、二阶段完成，不为等待自建编辑器推迟边界修复。** 每个阶段单独交付、复核，再进入下一批修改。

## 六、范围与取舍

### 本阶段必须完成

- 自动发现并定位主要边界问题；
- 跑通“确认规则 → 脚本生成修复候选 → 人工核对”的闭环；
- 验证至少一种能够降低描点和复核负担的标注流程；
- 保留原始依据、近似精度标注和回退能力。

### 暂不承诺

- 从 PDF 或四至文字一键生成准确边界；
- 无依据的自动裁剪、自动补齐所有空白区域；
- 完整的网页地图编辑平台；
- 将几何检查通过解释为官方核验通过。

QGIS 不需要自研，但仍有学习、配置和核验成本。本临时规划不沿用此前未经验证的固定工时估算；先通过代表性样例确定工作量，再决定扩大实施范围。

## 七、预计涉及的文件与模块

以下为规划位置，尚未创建或实现，具体命名以实施时确认为准：

- `scripts/check-zones.mjs`：几何检查与报告入口；
- `scripts/repair-zones.mjs`：按已确认规则生成修复候选；
- `scripts/lib/`：必要的检测或修复逻辑，避免重复实现；
- `package.json`：实际落地后接入检查命令；
- `data/zones.geojson`：人工复核通过后才更新工作副本；
- `data/releases/` 与 `data/current.json`：通过现有发布流程生成新快照、切换生效版本；
- 现有开发或维护文档：补充操作流程和检查结果解释。

空间计算优先评估项目已有的 Turf 技术路线；依赖选择与版本在实施时核实，不在本规划中安装或锁定。

## 八、验收与回退

### 验收重点

- 检查样例覆盖：共享边界、面积重叠、完全包含、跨学段重叠、自相交、MultiPolygon 和孔洞；
- 缝隙检查同时覆盖“有明确覆盖范围”和“没有覆盖依据”两种情况，后者不得直接报为漏划；
- 候选修复不会意外删除学区、破坏属性或改变无关区域；
- 修复前后对固定地址点进行查询对比，变化符合已确认的边界调整；
- 人工能根据问题图层找到位置，并对照原始文件核实；
- 操作说明能支持另一名成员独立完成一次修改与检查。

### 回退方式

候选数据与原数据分开保留，审核前不替换工作副本。已发布快照不原地修改；修复通过新版本发布，出现问题时将生效指针切回上一份可靠快照。

## 九、与总规划的衔接及需纠正的约定

本文件细化 P0-6，但对总规划中此前写得过于绝对的内容作如下澄清，实施前应同步修订总规划：

1. **先检查不等于自动修复**：修复脚本只能执行有依据、已确认的规则。
2. **不能无条件查缝隙**：只有明确应覆盖的范围或应共边关系，才能判定遗漏。
3. **不能一律先收缩再求交**：先保留原始检测事实，再验证容差策略。
4. **QGIS 是优先试用方案，不是零成本保证**：先跑通样例，再固定团队流程。
5. **大模型判断不能替代确定性检查**：当前核对已由大模型参与，但结论不可重放、不具备确定的判据，不能作为发布依据；它与脚本检查是互补关系，不是互相替代。

最终目标不是让地图看起来“没有缝”，而是让每一次边界改动都有依据、能复现、能检查、能回退。
