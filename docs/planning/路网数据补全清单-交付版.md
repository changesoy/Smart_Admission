# 泰安城区路网数据补全与修正清单（交付版）

> 数据文件：`data/roads.geojson`（FeatureCollection，当前 58 条；本文 64 条为 2026-10-24 生成时的基线）
> 用途：作为学区边界的唯一几何依据。学区四至原文见
> `docs/泰山区2025四至_原文全文.md`，分界线名称以
> `docs/泰山区学校四至范围_分界线名称清单.md` 为准。
> 生成日期：2026-10-24

---

## 0. 总体要求

1. **一条路只保留一条中心线**。双向分幅、上下行、辅路一律不得各自成线。
2. 几何类型统一 `LineString`（除非同一条路确有互不相连的独立段，才用 `MultiLineString`，
   且段与段之间必须能说清为什么不相连，例如立交跨线）。
3. 顶点不必加密，但**每个交叉口必须有顶点**，否则边界无法在路口转折。
4. 坐标系统一 WGS84，保留 5–6 位小数。
5. 属性沿用现有字段：`roadId / name / type / important / dataStatus / note`。
6. 修改请直接改 `data/roads.geojson`，**不要动 `data/releases/` 下的已发布快照**。

问题共 7 类，数量如下：

| 类别 | 问题                         |  数量 | 优先级 |
| ---- | ---------------------------- | ----: | ------ |
| A    | 线中断（端点簇之间断开）     | 11 条 | 高     |
| B    | 重复双线（同一条路画了两条） | 16 组 | 高     |
| C    | 清单有、数据缺失的线         | 19 条 | 高     |
| D    | 手绘示意线（非实测几何）     | 13 条 | 中     |
| E    | 只有 2 个顶点的退化线        |  4 条 | 中     |
| F    | 坐标越出城区范围             |  2 条 | 低     |
| G    | 端点悬空（接不上任何其他线） | 48 条 | 低     |

## B. 重复双线（重点）

判定方法：沿每条线每 20 米采样，统计其采样点落在**另一条线** 40 米内的比例。
比例高、平均间距 5–25 米，即同一条路的两次绘制（双向分幅或重复描摹）。
**处理原则：合并为一条中心线，保留完整、连续的一侧或取两线中点，不得两条都留。**

## G. 端点悬空（48 条，低优先）

按 40 米容差统计，48 条线存在端点接不上其他线的情况。多为：

- 线段在路口前提前结束（差 40–150 米）
- 立交/桥梁两侧不连通

处理建议：统一做端点吸附（吸附到最近顶点），阈值 30–40 米；超过阈值的按影像确认。
注意：本项与 A 类部分重叠，可合并处理。

## I. 验收标准

1. 同一 `name` 只允许 1 个要素；如确需多段，段间距离必须 >300 米并写明原因。
2. 任意两条线在 40 米内并行且重合长度 >300 米 → 判为重复双线，验收不通过。
3. 交叉口处必须有顶点，且同一路口的两条线端点相距 ≤5 米。
4. 所有坐标落在 `116.85–117.30 / 35.85–36.35`。
5. `npm run validate:data` 通过；JSON 合法、无占位文字。
6. 文件行尾为 CRLF（仓库 `.gitattributes` 规定 `data/** text eol=crlf`）。
