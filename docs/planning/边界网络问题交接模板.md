# 边界网络问题交接模板

> 用途：A（边界数据）、B（契约与工具）、C（学区绑定）之间交接问题，避免口头往返
> 相关契约：`docs/planning/统一边界网络数据契约与ID规则.md`

## 一、数据缺口单（提出方 → 角色 A）

适用于：缺路、断头、双线、过冲、欠伸、名称/别名缺失、顶点未共点、需要新增边界要素。

```json
{
  "issueId": "gap-2026-0001",
  "reportedBy": "C",
  "reportedAt": "2026-11-18",
  "type": "missingFeature",
  "target": {
    "featureId": null,
    "legacyRoadId": null,
    "canonicalName": "泮河大街",
    "zoneIds": ["zone_013"]
  },
  "expected": "需将该段中心线补入边界要素，并在与迎胜路交点处共点",
  "evidence": "官方四至「南至泮河大街」，现有要素仅覆盖其东半段",
  "impact": ["zone_013 南边界无法闭环"],
  "priority": "high",
  "status": "reported"
}
```

## 二、裁定申请单（提出方 → 裁定人）

适用于：官方原文与现有几何冲突、多个候选要素无法自动区分、存在多条可行路径。

```json
{
  "issueId": "rule-2026-0001",
  "reportedBy": "C",
  "reportedAt": "2026-11-18",
  "zoneId": "zone_006",
  "edge": "东",
  "originalText": "东至双龙河",
  "candidates": [
    { "featureId": "bf_000127", "canonicalName": "唐王河", "distanceM": 40 },
    { "featureId": "bf_000041", "canonicalName": "双龙河", "distanceM": 900 }
  ],
  "recommendation": "采信唐王河，与相邻学区共用边界一致",
  "status": "pendingRuling"
}
```

裁定结论由角色 C 写入 `boundaryRulings`，`boundaryText` 保持官方原文不改。

## 三、状态流转

```text
reported → analyzed → approved → implemented → topologyBuilt → zoneBound → verified
```

- `reported`：已提交，等待受理
- `analyzed`：已定位，给出处理方案或驳回理由
- `approved`：方案确认，可执行
- `implemented`：角色 A 已修改边界要素
- `topologyBuilt`：角色 B 已重建节点与边
- `zoneBound`：角色 C 已完成学区引用
- `verified`：三方确认，可进入下一批次

## 四、提交约定

- 单个问题一个条目，不合并多个诉求
- 必填：对象、期望、证据、影响、优先级
- 涉及几何修改时必须写明期望的起止节点或道路名，不要只写“这里不对”
- 状态变更只由承接方更新，提出方不改状态
- 批次验收前，`reported` 与 `analyzed` 的条目必须清零或明确延后
