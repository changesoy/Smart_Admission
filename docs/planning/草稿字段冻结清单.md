# 草稿字段冻结清单

> 状态：已冻结（2026-11-17），交付角色 C
> 依据：`统一边界网络数据契约与ID规则.md` 9.4、9.6；`地图点选式学区边界工具实施方案.md` 2.2
> 效力：本清单是草稿 `zone_draft` 的字段级冻结版本。与前两份文档中的旧示例冲突时，以本清单为准（两处示例已同步修订）
> 变更：新增、删除或改名草稿字段，须由 B 确认并提交契约变更请求；C 不得在导出文件中另造字段

---

## 一、冻结原则

1. 草稿只保存引用，不保存坐标；任何经纬度都视为缺陷。
2. 草稿按**正式步骤**绑定：`stepId` 一律沿用 `zone_specs.v2.json`，不新建、不改序、不改写原文。
3. 环的有序边序列由步骤顺序拼接派生，草稿不再保存第二份环级边列表。
4. 草稿不是权威数据，不进发布包，不写 `id_registry`。
5. 编辑器界面状态（缩放、图层、高亮、面板折叠）不得写入导出文件。

## 二、顶层字段

| 字段 | 类型 | 必填 | 取值与规则 |
| --- | --- | --- | --- |
| `draftId` | string | 是 | `draft_<zoneId>_<YYYYMMDD>_<两位序号>`，同一学区同日序号递增；草稿创建后不再改名 |
| `schemaVersion` | integer | 是 | 固定 `1` |
| `zoneId` | string | 是 | 必须存在于 `zone_specs.v2.json` |
| `boundaryText` | string | 是 | 必须与 `zone_specs.v2.json` 中该学区原文逐字一致，只读，草稿内不得改写 |
| `status` | string | 是 | `editing` / `readyForReview` / `rejected` / `imported` |
| `createdBy` | string | 是 | 操作人标识，如 `用户`，不使用账号或邮箱 |
| `createdAt` | string | 是 | `YYYY-MM-DD` |
| `updatedAt` | string | 是 | `YYYY-MM-DD`，每次状态或内容变化时更新 |
| `rings` | array | 是 | 见第三节；`editing` 允许为空数组，`readyForReview` 起必须恰有 1 个 `outer` |
| `operations` | array | 是 | 见第五节；允许为空数组 |
| `rejectReason` | string \| null | 否 | 仅 `status=rejected` 时必填；其他状态必须为 `null` |

`status` 取值：

- `editing`：编辑中，允许步骤未绑定、环未闭合；
- `readyForReview`：已全部绑定并通过本地校验，等待人工审核；
- `rejected`：人工驳回，可继续编辑回到 `editing`；
- `imported`：已导入正式 `zone_specs.v2.json`，只读归档。

## 三、`rings[]`

| 字段 | 类型 | 必填 | 取值与规则 |
| --- | --- | --- | --- |
| `role` | string | 是 | `outer` / `hole` |
| `appliesToRingId` | string \| null | 否 | `hole` 必填，取本学区 `outer` 环的正式 `ringId`（如 `zr_000002`）；`outer` 必须为 `null` |
| `steps` | array | 是 | 见第四节 |

规则：

- 一个草稿最多一个 `outer`；飞地（多外环）未启用，出现即拒绝。
- `role=hole` 至少 3 个步骤，且环内不得出现 `side=排除` 的步骤。
- 排除区域按契约 9.6 判定：与外环相接的按凹口并入 `outer`，`side=排除` 的步骤照常绑定边；只有完全内嵌、独立闭包的才建 `hole`。
- 导入时 `ringId` 由正式数据沿用，不在草稿中出现。

---

## 四、`steps[]`

| 字段 | 类型 | 必填 | 取值与规则 |
| --- | --- | --- | --- |
| `stepId` | string | 是 | 必须存在于该学区对应环的正式步骤中 |
| `edgeRefs` | array | 是 | `[{ edgeId, direction }]`，`editing` 时允许空数组 |

`edgeRefs[]`：

| 字段 | 类型 | 必填 | 取值与规则 |
| --- | --- | --- | --- |
| `edgeId` | string | 是 | 必须存在于 `network_edges.json` |
| `direction` | string | 是 | `forward` / `reverse` |

规则：

- 每个正式步骤在草稿中恰好出现一次，数组顺序必须与正式步骤顺序一致；`stepId` 数值大小不代表顺序（如 zone_006 为 `zs_0000117`、`zs_0000118`、`zs_0000009`……）。
- 禁止新增 `stepId`、禁止删除步骤、禁止调整顺序；步骤拆分或合并属于契约层变更，不在草稿内处理。
- 草稿不复制 `side`、`text`、`sourceType`、`rulingIds`，这些字段读取正式数据；如需展示只读引用。
- 每条边必须 `lifecycle=active` 且 `boundaryEligible=true`；`retired`、`deprecated`、不可作边界的要素一律不可选。
- 步骤内相邻边按 `nodeId` 首尾相接；相邻步骤首尾相接；环最后一步终点等于第一步起点，闭合误差必须为 0。
- 同一环内不得重复引用同一 `edgeId`。
- 只允许整边引用；需要半条边说明网络缺节点，退回 A 补节点，不得裁剪坐标。
- `readyForReview` 时每个步骤至少 1 条 `edgeRefs`。

---

## 五、`operations[]`

| 字段 | 类型 | 必填 | 取值与规则 |
| --- | --- | --- | --- |
| `type` | string | 是 | `selectEdge` / `unselectEdge` / `reverseEdge` / `clearStep` / `clearRing` |
| `stepId` | string | 是 | `clearRing` 时可为 `null`；其余必填 |
| `edgeId` | string \| null | 是 | `selectEdge`、`unselectEdge`、`reverseEdge` 必填；其余必须为 `null` |
| `decidedBy` | string | 是 | 操作人标识 |
| `decidedAt` | string | 是 | `YYYY-MM-DD` |
| `textRef` | string | 否 | 写入时必须等于该步骤当前 `text`；用于审计，不参与绑定 |

规则：

- 数组顺序即操作顺序，不另设序号。
- 撤销、重做只写补偿操作（`unselectEdge`、`clearStep`、`clearRing`），禁止删除历史操作记录。
- 操作记录只用于审计与复现，不得反向推导业务决定；最终状态以 `rings[].steps[].edgeRefs` 为准。

## 六、禁止字段与禁止行为

禁止字段（出现即校验失败）：

```text
coordinates / geometry / ring / vertices / from / to / ringVertexSpan / polyline / latlng
featureId + fromNodeId + toNodeId 组合作为绑定结果
```

禁止行为：

- 保存自由坐标、补画直线、按最近距离或最短路径静默选择；
- 修改 `boundaryText`、`side`、`text`、`sourceType`、`rulingIds`；
- 创建或回收 `ringId`、`stepId`、`edgeId`、`featureId`；
- 直接写 `boundary_features`、`network_nodes`、`network_edges`、`zone_specs.v2.json`、`zones.geojson`；
- 编辑器自行判定连通：只读节点的 `connectionType`，几何相交不等于连通。

## 七、校验清单（`validate-zone-draft` 必查）

实现时点：C 阶段 4 之前交付；以下为冻结的检查项，编号可用于测试用例名。

| 编号 | 检查 | 处理 |
| --- | --- | --- |
| D01 | `schemaVersion`、必填字段、字段类型、枚举合法 | 拒绝 |
| D02 | `draftId` 格式与命名空间 | 拒绝 |
| D03 | `zoneId` 存在于 `zone_specs.v2.json` | 拒绝 |
| D04 | `boundaryText` 与正式原文逐字一致 | 拒绝 |
| D05 | `stepId` 无缺失、无多余、无重复，顺序与正式一致 | 拒绝 |
| D06 | `edgeId` 均存在于 `network_edges.json` | 拒绝 |
| D07 | 边 `active`、`boundaryEligible=true` | 拒绝并说明原因 |
| D08 | `direction` 枚举合法 | 拒绝 |
| D09 | 步骤内边按 `nodeId` 连续 | 拒绝并给出断点 |
| D10 | 步骤之间按 `nodeId` 连续 | 拒绝并给出断点 |
| D11 | 环首尾闭合，误差为 0 | 拒绝 |
| D12 | 恰有 1 个 `outer`；`hole` 的 `appliesToRingId` 正确、≥3 步、无 `side=排除` | 拒绝 |
| D13 | `side=排除` 步骤只能出现在 `outer`，且必须绑定边 | 拒绝 |
| D14 | 同一环内无重复 `edgeId` | 拒绝 |
| D15 | 不含第六节禁止字段 | 拒绝 |
| D16 | `operations` 与 `stepId`、`edgeId` 匹配，`textRef` 一致 | 拒绝 |
| D17 | `readyForReview` 时所有步骤均已绑定 | 拒绝 |
| D18 | 同一输入与操作序列导出字节一致 | 构建测试断言 |

导入规则：`import-zone-draft` 只回写步骤 `edgeRefs`，不改步骤定义、不改原文、不分配新 ID；校验失败整体不落盘。

## 九、暂不冻结的事项

- 多 `outer`（飞地）表达：当前 14 个学区均不需要，启用前另行出契约变更。
- 步骤文本变更后的草稿失效策略：以 `stepId` 为准，文本差异只提示；如步骤被退役，相关草稿标记 `rejected`。
- 财源街、擂鼓石路、环山东路三条名称归一：属 B6 裁定，不影响本清单字段结构。
