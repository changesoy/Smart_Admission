# 节点/边生成器规格与样例交接

> B8 交付物。本文冻结 C 实现节点/边生成器时的输入输出、稳定身份、ID 分配、幂等、dry-run、事务写入和验收样例。
> 数据结构以《统一边界网络数据契约与ID规则》为准；本文只补足生成过程，不另建第二套数据契约。

## 一、目标与非目标

生成器把唯一坐标源 `boundary_features.v2.geojson` 转成无坐标的拓扑节点与拓扑边：

```text
boundary_features.v2.geojson + connection_decisions.json
                         + previous network_nodes/network_edges
                         + id_registry.json
                                      ↓
                         network_nodes.json
                         network_edges.json
                         id_registry.json
                         generation report
```

生成器负责：

- 为每个要素 part 的首尾建立节点；
- 按连接裁定把完全共点的 placement 组成连通、非连通或条件节点；
- 按 active、connected 节点切分每个要素 part，生成规范方向的拓扑边；
- 复用上一版稳定实体，分配新 ID，退役被拆分、合并或替换的实体；
- 在写入前完成全量校验，并以同一事务提交节点、边和注册表；
- 输出可复核的拟新增、复用、退役和替代关系。

生成器不负责：

- 修改、吸附、插入或删除 `boundary_features` 坐标；
- 把几何相交自动解释为拓扑连通；
- 修改 `zone_specs`、绑定 `edgeRefs` 或重排学区步骤；
- 根据名称、最近距离或最短路径猜测连接关系；
- 继续生成旧 `ix_*` 交点作为正式节点。

## 二、命令与输入

### 2.1 命令

C 提供一个 Node ESM 入口：

```powershell
node scripts/generate-network.mjs
node scripts/generate-network.mjs --write
```

也可以走统一入口 `scripts/main.mjs`，它只做路由、原样转发参数并透传退出码，子脚本仍可单独执行：

```powershell
node scripts/main.mjs network:generate --effective-date 2026-11-21
npm run cli -- network:generate --help
node scripts/main.mjs --list          # 查看全部子命令
```

支持参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--features <path>` | `data/boundary_features.v2.geojson` | 唯一坐标源 |
| `--decisions <path>` | `data/network_connection_decisions.json` | 连接裁定；不存在时只允许无歧义端点建点 |
| `--previous-nodes <path>` | `data/network_nodes.json` | 上一版节点；首次构建可不存在 |
| `--previous-edges <path>` | `data/network_edges.json` | 上一版边；首次构建可不存在 |
| `--registry <path>` | `data/id_registry.json` | ID 注册表，正式运行必须存在 |
| `--nodes-out <path>` | `data/network_nodes.json` | 节点输出 |
| `--edges-out <path>` | `data/network_edges.json` | 边输出 |
| `--report <path>` | 无 | 显式指定时才写报告文件 |
| `--effective-date <YYYY-MM-DD>` | 必填 | 新实体 `createdAt`，禁止读取系统当前日期 |
| `--write` | false | 不带时为严格 dry-run |
| `--help` | false | 打印参数说明 |

未知参数、缺少参数值或输入 JSON 无法解析必须失败，不得忽略。

### 2.2 输入快照

生成前一次性读取并冻结全部输入字节及 SHA-256。生成过程中输入文件变化必须失败，不得把前后两个快照混合使用。

正式重建必须读取上一版节点、上一版边和注册表。上一版节点、上一版边首次不存在时分别视为空数组；正式注册表必须存在，缺失时按 IO 错误退出。文件存在但结构错误时不得降级为空。

### 2.3 连接裁定

`network_connection_decisions.json` 是几何相交到拓扑关系的可重放输入：

```json
{
  "schemaVersion": 1,
  "decisions": [
    {
      "decisionId": "ncd_000001",
      "connectionType": "connected",
      "placements": [
        { "featureId": "bf_900001", "partIndex": 0, "vertexIndex": 1 },
        { "featureId": "bf_900003", "partIndex": 0, "vertexIndex": 1 }
      ],
      "rulingIds": [],
      "note": "合成样例：平面交叉"
    }
  ]
}
```

规则：

- `decisionId` 只用于审计和稳定排序，不进入正式实体 ID；
- `placements` 先按 `featureId/partIndex/vertexIndex` 升序规范化；
- `connected` 的全部 placement 坐标在 7 位小数下必须完全相同；
- 不同 feature 的 part 端点完全共点时仍须有 `connected` 裁定，生成器不得仅凭共点自动换边；
- `nonConnectingCrossing` 可以表达几何相交但不可换边；其各 placement 不合并成一个可通行节点；
- `conditional` 必须有非空 `rulingIds` 或结构化条件；默认不得用于正式学区路径；
- 同一 placement 不能同时出现在互相冲突的裁定中；
- 未裁定的多要素共点、交叉或近邻只进报告，不得自动生成正式 intersection；
- A 负责让应连通位置在边界要素中完全共点，B 负责连接语义裁定，C 只执行裁定。

## 三、输出结构与排序

### 3.1 文件根结构

```json
{
  "schemaVersion": 1,
  "nodes": []
}
```

```json
{
  "schemaVersion": 1,
  "edges": []
}
```

节点、边字段遵循契约第七、八章，不保存 `coordinates`、`geometry` 或其他坐标副本。

### 3.2 确定性序列化

- UTF-8 无 BOM、LF、两空格缩进、文件末尾一个换行；
- 对象字段按本规格样例顺序输出；
- `nodes` 按 `nodeId` 升序；`edges` 按 `edgeId` 升序；
- `placements` 按 `featureId/partIndex/vertexIndex` 升序；
- `supersedes`、`supersededBy` 按 ID 升序；
- 坐标比较统一使用 7 位小数；`lengthM` 固定到 0.1 米；
- 节点和边主体不得写入运行时间；`createdAt` 沿用既有实体值，新实体使用显式 `--effective-date`，禁止直接读取当前系统时间；
- 报告可以带 `generatedAt`，但不参与主体文件字节一致性验收。

## 四、生成规则

### 4.1 placement 候选

对每个 active boundary feature 的每个 part：

1. part 首尾顶点各建立一个 terminal 候选；
2. 读取连接裁定中的 placement；
3. 读取上一版 active 节点的 placement，用于稳定身份匹配；
4. 去重后验证 `partIndex/vertexIndex` 均有效；
5. 若闭合 part 只有一个切分节点，必须报告需增加 control 节点，不得生成自环边。

`boundaryEligible=false` 的要素仍可生成用于展示或审计的节点和边，但生成边必须继承 `boundaryEligible=false`，不可被学区引用。

### 4.2 节点身份与复用

节点稳定身份不等于坐标。匹配顺序固定为：

1. 显式迁移关系或上一版同一 `nodeId` 的 placement 集合；
2. 上一版唯一节点，其规范化 placement 集合与候选完全相同；
3. 人工确认的节点延续关系；
4. 否则视为新节点。

仅坐标相同不得复用 ID。小范围几何校正后 placement 三元组不变时保留原 `nodeId`；顶点插入导致 `vertexIndex` 变化时，应通过上一版引用解析和沿线位置重定位确认仍为同一节点，不能按新下标重新编号。

新节点分配前按以下稳定候选键排序：

```text
nodeType | connectionType | sorted(featureId:partIndex:vertexIndex)
```

节点拆分或合并必须创建新 ID，旧节点退役，并双向记录 `supersedes/supersededBy`。

### 4.3 边切分与身份

对每个 feature part，把 active、connected 节点按 `vertexIndex` 升序排列；每两个相邻节点生成一条边：

- `fromVertexIndex < toVertexIndex`，该顺序即 `forward`；
- `fromNodeId`、`toNodeId` 对应端点 placement；
- `lengthM` 从唯一坐标源重算：逐段调用 `network-schema.mjs` 的 `approxMeters` 后求和，最终四舍五入到 0.1 米；C 若要替换测距算法，必须先修改契约、样例快照和全部调用方；
- `boundaryEligible` 继承要素；
- `verificationStatus` 不得高于来源要素和两端节点的最低可信状态；
- part 的首尾线段必须完整覆盖，内部不得重叠或遗漏；
- 非连通交叉不能切出可换边的共享节点。

边身份匹配键为：

```text
featureId | partIndex | fromNodeId | toNodeId
```

内部顶点或 `lengthM` 改变而匹配键不变时保留 `edgeId`。起点、终点、所属要素或 part 改变时必须创建新 ID。新增节点导致旧边拆分时，旧边退役，新边记录 `supersedes`。

新边分配前按以下稳定候选键排序：

```text
featureId | partIndex | fromVertexIndex | toVertexIndex | fromNodeId | toNodeId
```

### 4.4 ID 注册

- 生成器只调用 `scripts/lib/id-registry.mjs` 的分配和登记能力，不自行拼接下一个 ID；
- 正式分配前必须深拷贝注册表，在内存中完成全部候选排序和分配；
- dry-run 可以展示拟分配的 ID，但不得修改内存外的注册表或任何文件；
- 注册表 counter 必须等于历史最大已分配序号，不能因退役而回退；
- 新节点、新边都要登记 `entityType`、`lifecycle`、`createdAt`、迁移关系；
- 已登记 ID 永不删除、永不转给其他实体。

## 五、dry-run、写入和退出码

### 5.1 严格 dry-run

不带 `--write` 时：

- 不创建、修改、删除任何文件，包括报告、临时文件和注册表；
- stdout 输出机器可读 JSON 报告，stderr 输出简短中文摘要；
- 报告列出输入哈希、拟复用、新增、退役、替代、错误和警告；
- dry-run 前后工作区文件字节和注册表计数器必须完全一致；
- `--report <path>` 是唯一允许的 dry-run 写操作，必须由调用者显式给出。

### 5.2 原子批次写入

带 `--write` 时按一个事务提交 `network_nodes.json`、`network_edges.json` 和 `id_registry.json`：

1. 在内存中生成并通过全部门禁；
2. 序列化三个最终字节串并计算 SHA-256；
3. 写入各目标同目录的唯一临时文件；
4. 重新读取临时文件，校验 JSON、哈希和交叉引用；
5. 保存旧文件恢复副本；
6. 替换三个正式文件；
7. 任一步失败则恢复全部旧文件；
8. 成功后清理临时与恢复文件并输出报告。

禁止出现节点、边已经更新但注册表仍是旧版本的中间成功状态。

### 5.3 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 生成和校验成功，可以有 warning |
| `1` | 输入可读取，但违反数据、拓扑或裁定规则 |
| `2` | 参数、文件读取、JSON 解析或写入事务失败 |

## 六、写入前门禁

生成器必须和 `validate-network` 共用纯校验逻辑，不复制规则。至少检查：

- 所有 ID 格式、唯一性、注册表登记和 counter 一致；
- placement 指向存在的 active feature、part 和顶点；
- connected 节点所有 placement 完全共点；
- intersection 至少包含两个不同 feature；
- 每个 feature part 首尾都有 active 节点；
- 边的端点 placement 与顶点范围一致；
- `fromVertexIndex < toVertexIndex`，无自环；
- 每个 feature part 完整覆盖、无重叠、无遗漏；
- active 边内部不存在未切分的 active connected 节点；
- `lengthM` 重算误差不超过 0.1 米；
- lifecycle 与 `supersedes/supersededBy` 双向一致；
- 输出不含坐标副本。

任一 error 都禁止写入；warning 必须进入报告。

## 七、幂等与变更场景

必须通过以下测试：

1. 同一输入连续生成两次，第二次不分配 ID，节点和边文件字节完全一致；
2. 调换无语义输入数组顺序，输出字节不变；
3. dry-run 前后正式数据、注册表、报告目录和临时文件均无变化；
4. 要素内部增加普通顶点，节点和边 ID 保持不变；
5. 新增 connected 节点导致旧边退役和两条新边产生，迁移关系完整；
6. 删除错误节点导致多边合并时，旧边退役并产生新边；
7. nonConnectingCrossing 不产生跨要素可换边节点；
8. 模拟三个目标中任一替换失败，全部文件恢复旧字节；
9. 全部新 ID 按稳定候选键分配，不受输入遍历顺序影响。

## 八、交接样例

最小样例位于：

```text
scripts/fixtures/network-generator/minimal/
```

文件：

| 文件 | 用途 |
| --- | --- |
| `boundary_features.geojson` | 4 条矩形边 + 1 条竖向穿越线 + 1 条水平非连通穿越线 |
| `connection_decisions.json` | 一个 connected 交叉、一个 nonConnectingCrossing |
| `previous_network_nodes.json` | 上一版已存在的左下角节点，用于验证 ID 复用 |
| `previous_network_edges.json` | 首次样例为空 |
| `id_registry.json` | 已登记 `bn_000001`，新 ID 从后续序号分配 |
| `expected_network_nodes.json` | 预期节点快照 |
| `expected_network_edges.json` | 预期边快照 |
| `expected_id_registry.json` | 预期注册表快照 |
| `README.md` | 样例命令和验收断言 |

样例使用 `bf_900001` 起的保留测试 ID，不得复制进生产注册表。它不依赖泰安真实要素，也不受 A 的数据修复进度影响。

真实冒烟在合成样例通过后进行：优先选 `zone_032` 涉及的北上高大街、东湖路、唐王河、天烛峰路四个要素，只验节点与边生成；在 B 完成步骤环序审计前，不据此自动生成草稿或认定环已闭合。

## 九、已知阻塞与边界

- `bf_000049 虎山东路` 的 4 处连续重复顶点会形成零长度段；A 修复前禁止全量正式写入，生成器必须显式报错；
- high 缺口单和别名缺失不阻塞合成样例，但会阻塞部分真实学区的 B10 绑定；
- 旧 `build-intersections.mjs`、`network.mjs` 生成的是 `ix_*` 和 `intersections.geojson`，不是本规格的正式生成器；
- B8 完成只表示 C 的实现输入已冻结，不代表 B9 验收通过；
- B9 必须抽样复核共点、切分、规范方向、ID 复用、双次构建和事务回滚。
