# 边界拓扑自动化工作流

## 目标

本项目构建的是学区边界拓扑，不是道路通行网络。道路、河道、铁路和其他边界要素只要形成有效几何交点，就作为边界可转折节点；桥梁、隧道、立交和现实通行能力不参与连接判断。

## 四阶段流程

1. 导入官方学区四至文本与原始边界要素坐标，不依赖人工逐点维护。
2. 将文本整理为有序步骤，脚本计算严格交点、三米内端点吸附、贯通缺口和重叠段。
3. 通过可视化工具处理欠伸、过冲、重复线、近邻双交点和无法自动修复的几何问题。
4. 在边界选择工具中按环向绑定边，校验连续、闭合、自交和共享边一致性后落盘。

## 自动交点规则

- 严格线段相交自动插入双方顶点并连通。
- 端点到另一要素三米内时自动吸附并连通。
- 夹角至少 35 度的贯通缺口在三米内自动插点并连通。
- 三至十米的贯通缺口只进入报告，不自动修改几何。
- 一米内的重复物理交点先聚类，避免同一位置重复建点。
- 共线重叠只进入报告，不自动决定保留哪条要素。

## 近邻 anchor 规则

同一边界要素上三十米内的多个物理交点组成近邻组，但不做链式扩散。每组只保留一个逻辑交点，其他交点仍保留在几何中但不进入正式连接裁定。

anchor 依次按以下规则选择：

1. 距组中心最近，距离按 0.01 米量化，最小值 0.5 米内视为并列。
2. 河流优先于同名河畔道路。
3. 节点类型按 cross、tee、multi、end 排序。
4. 实体等级按河流或铁路、主干道路、普通道路排序。
5. 方位按南、西、北、东排序。
6. 使用稳定几何键兜底。

## 正式产物

- `data/boundary_features.v2.geojson`：插入和吸附后的唯一坐标源。
- `data/network_connection_decisions.json`：自动接受的逻辑边界交点。
- `data/network_nodes.json`：边界节点及其 placement。
- `data/network_edges.json`：按 active connected 节点切分的边。
- `data/id_registry.json`：节点和边的稳定 ID 登记。
- `reports/network/boundary-topology-plan.json`：规则命中、anchor 组和未解决几何问题。
- `reports/network/boundary-placement-remap.json`：插点前后顶点下标映射。

## 门禁

- 坐标统一保留七位小数。
- connected 节点的全部 placement 必须完全共点。
- 插点后必须通过 placement remap 复用可复用的历史节点和边。
- 首次写入后再次生成必须零新增、零退役且三文件字节一致。
- 学区环必须按正式步骤顺序连续闭合、无自交，才能写入 `edgeRefs`。
