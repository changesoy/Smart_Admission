## 一、状态与优先级口径

状态流转：

```text
reported → analyzed → approved → implemented → topologyBuilt → zoneBound → verified
```

另有 `deferred`：B 已确认当前批次不做，保留单据。

优先级：

- `high`：阻塞 B10 步骤绑定或环闭合，本批必须 `implemented`；
- `medium`：可用现绘制或裁定过渡，不阻塞绑定，但会影响 B11/B12 精度；
- `low`：仅在未来按原文调整时才需要，当前已由裁定过渡。

## 四、A 的交付要求

- 一个缺口一条要素，不合并多个诉求；新增要素必须写入 `data/boundary_features.v2.geojson` 并登记 `id_registry.json`。
- 每条要素至少给：`featureId`、`canonicalName`、`aliases`、`featureType`、`boundaryEligible`、`sourceType`、`sourceName`、`verifiedDate`、`verificationStatus`、`geometryAccuracy`。
- 几何统一 `LineString`，WGS84，7 位小数；与既有要素相交处必须是两要素中完全相同的顶点，不得只求“近似重合”。
- 墙类用 `featureType=wall`；面状范围（艾洼小区）转闭合 `LineString` 或人工裁定线。
- 完成后把状态推进到 `implemented`，写明改动的 `featureId` 列表与提交号。
- 无法按原文补录时，把状态置为 `analyzed` 并写明原因与替代方案，不静默改线。
