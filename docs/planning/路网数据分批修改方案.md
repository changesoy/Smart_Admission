# 路网数据分批修改方案

> 依据：`docs/planning/路网数据补全清单-交付版.md`（A–H 七类问题，清单计 11+16+19+13+4+2+48 项；P0 实测见第 2 节）
> 目标文件：`data/roads.geojson`（基线 64 要素 / 130 段 / 5244 点）
> 约束：不改 `data/releases/`、不改 `data/current.json`；文件行尾 CRLF；改完 `npm run validate:data` 必须通过

---

## 1. 总体策略

七类问题里，**A（线中断）、B（重复双线）、G（端点悬空）本质是同一件事**：把同一条路的几何收敛成"一条连续中心线"。因此不按类别写七套代码，而是建 4 个可复用脚本，按批次调用：

| 脚本 | 职责 | 服务类别 |
| --- | --- | --- |
| `scripts/roads/audit.mjs` | 只读体检，输出各问题的数量与清单到 `reports/` | A/B/C/D/E/F/G |
| `scripts/roads/merge-dual.mjs` | 同路多线并中心线、去折返 | B（含 A 的重复段） |
| `scripts/roads/connect.mjs` | 端点吸附与断口接续 | A、G |
| `scripts/roads/normalize.mjs` | `roadId` 重排、字段补全、CRLF 规范化 | H、I-6 |

每个脚本都满足：输入输出都是 `data/roads.geojson`、可重复执行（幂等）、默认 dry-run 只打印差异，加 `--write` 才落盘。

1. 运行 `audit.mjs`，把七类问题的**当前数量清单**写入 `reports/roads-audit-<日期>.json`。
2. 以 `git tag` 或分支打一个只读基线（例：`roads-baseline`）。
3. **判定门禁**：若某类实际数量与文档表格差异 >20%，先回写文档再动手，避免按过期清单改。

### P1 双线合并（决定边界贴合度，优先级最高）

处理顺序：**先跨要素（B2）定去留，再要素内（B1）批量合并**，因为 B2 删错会影响 B1 的配对。

- **B2 四组**：环山路↔环山东路（环山东路 79% 被覆盖、重合 4.84km，判为副本，删环山东路要素）；五马街↔顺河街（100% 重合 6.98km、平均 16m，同一模板线画两遍）；南湖大街↔五马街（46%）、南湖大街↔顺河街（43%），示意线压到真实道路上。后三组涉及两条待重描的示意线，留到 P4 处理。
- **B1 三十四组**（P0 实测，清单原表 37 行、"13 条路"非组数）：**整段删除被完全覆盖的一侧（single-side）**，不做中点平均，避免整条线偏移导致与交叉路口错位；判定参数沿用文档：每 20m 采样、40m 邻域、覆盖率 ≥85%。
- **特例**：擂鼓石大街 `part1` 首尾同点属于折返，按"裁到离起点最远点"修形；同批补 A1 中擂鼓石大街约 1000m 的东段断口。
- 产出：改动要素的 `note` 追加"P1 去除同路并行副本 N 段"；`centerlineMethod` 字段在 P5 统一补。

**验收**：I-2（40m 内并行且重合 >300m 判不通过）除下列例外应为零；段数应大幅下降。

#### P3 增补：同簇贴合与往返叠画展开（2026-10-24，已完成）

A1 复核后，梳洗河与擂鼓石大街两条都**不是缺线**，而是脚本口径问题：

| 对象 | 原报断口 | 真实原因 | 处理 |
| --- | ---: | --- | --- |
| 梳洗河 | 2883 m | 2.99 km 的 OSM way 430063084 早已在数据里（part1），与上游 part 首尾只差 11 m；体检 A 类只统计"跨簇"距离，才把两端真实端点间 2883 m 报成断口 | 同簇端点直接拼接 → **1 段 10.02 km**，无需补线 |
| 擂鼓石大街 | 962 m | part#1 是 `A→B→A→C→A` 的往返叠画闭合环（5.20 km 实际只覆盖 2.6 km），首尾同点让 C 端藏在环内，无法与西侧 part 相接 | 取两掉头点之间的简单路径 `B→A→C`（去掉回程 2.6 km），再与西侧 part 相接 |

`connect.mjs` 相应修正三处：

1. 新增同簇（≤30 m）端点直接拼接，不做夹角校验；**铁路例外**（双轨端点本就相距约 20 m，合并会把 53 km 双轨折成回折线）。
2. `unfoldDualLoop` 改为"掉头点识别"：单掉头（`A→B→A`）保留去程；双掉头（`A→B→A→C→A`）保留两掉头点间的简单路径，并要求保留段与去掉段长度相近（0.7–1.4 倍），以排除真实环形路/hairpin。
3. 修正拼接时"先删后写"造成的下标错位（改为先写小下标、再删大下标）。

结果：**80 段 → 78 段 / 3876 点**；A 线中断 **10 → 9**、I-1 **9 → 8**、G 46 不变；B 类无新增（B1 3 组仍为京沪铁路双轨、B2 3 组仍为三条示意线）；`validate:data` 通过。

A1 最终口径（9 条，全部保留断开，P5 逐条记录）：龙潭路 1663 m、京沪铁路 1118 m（越界）、擂鼓石大街 1073 m（OSM 同位置同样断开）、迎胜路 901 m、御碑楼路 572 m、东岳大街 290 m（166°/7° 反向）、长城路 252 m、虎山路 48 m（67°/66°）、环山路 30 m（1°/60°）。

## 3. 批次依赖与执行顺序

```
P0 体检 → P1 双线合并 → P3 断口接续 → P2 缺线补齐 → P4 示意线重标 → P5 收尾
                ↘（B2 跨要素判定）→ P2a 谢过城街
```

- P1 必须早于 P2/P3：双线未合并时补线，会与新线再撞出重复。
- P3 早于 P2：先把既有路网闭合，新线端点才有确定的交点可吸附。
- P4 可与 P2b/P3 并行（不同要素，互不重叠）。
- P5 必须在全部几何定稿后执行，字段补全才有意义。

| I-3 | 交叉口端点 ≤5m | 端点对最近距离 |
| I-4 | 坐标在 `116.85–117.30 / 35.85–36.35` | bbox 扫描 |
| I-5 | `npm run validate:data` 通过 | 直接调用 npm 脚本 |
| I-6 | 行尾 CRLF | 写入时统一 `.replace(/\r?\n/g, "\r\n")` |

每批结束的固定动作：`audit.mjs --check` → `npm run validate:data` → 提交（只提交 `data/roads.geojson`）。

---

## 5. 风险与回滚

- **误删风险（P1）**：跨要素重复判定容差只有 1m，先做 dry-run 输出配对清单，人工过一遍再 `--write`。
- **假线风险（P2/P4）**：严禁再生成 <10 顶点的模板直线；`audit.mjs` 对"顶点数 <10 且长度 >500m"的线直接报错。
- **越界回灌（F）**：裁剪后要确认没有把有效段一起裁掉，裁剪前后长度差 >5% 时提示人工确认。
- **回滚**：每批改动前 `git stash`/分支隔离；过程稿写 `reports/`（已被 `.gitignore` 忽略），不提交。
- **发布隔离**：全程不碰 `data/releases/2026.10.9/`，等全部批次验收通过后再单独走一次发布流程（`new-data-release.mjs` + `check-release.mjs`）。
