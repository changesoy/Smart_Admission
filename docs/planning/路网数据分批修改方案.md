# 路网数据分批修改方案

> 依据：`docs/planning/路网数据补全清单-交付版.md`（A–H 七类问题，清单计 11+16+19+13+4+2+48 项；P0 实测见第 2 节）
> 目标文件：`data/roads.geojson`（基线 64 要素 / 130 段 / 5244 点）
> 约束：不改 `data/releases/`、不改 `data/current.json`；文件行尾 CRLF；改完 `npm run validate:data` 必须通过

---

## 1. 总体策略

七类问题里，**A（线中断）、B（重复双线）、G（端点悬空）本质是同一件事**：把同一条路的几何收敛成"一条连续中心线"。因此不按类别写七套代码，而是建 4 个可复用脚本，按批次调用：

| 脚本 | 职责 | 服务类别 |
| --- | --- | --- |
| `scripts/roads/audit.mjs` | 只读体检，输出各问题的数量与清单到 `reports/` | A/B/C/D/E/F/G |
| `scripts/roads/merge-dual.mjs` | 同路多线并中心线、去折返 | B（含 A 的重复段） |
| `scripts/roads/connect.mjs` | 端点吸附与断口接续 | A、G |
| `scripts/roads/normalize.mjs` | `roadId` 重排、字段补全、CRLF 规范化 | H、I-6 |

每个脚本都满足：输入输出都是 `data/roads.geojson`、可重复执行（幂等）、默认 dry-run 只打印差异，加 `--write` 才落盘。

---

## 2. 批次划分

| 批次 | 内容 | 对象数 | 依赖 | 规模 |
| --- | --- | ---: | --- | --- |
| **P0** 基线体检 | 跑 `audit.mjs`，冻结当前 64 要素基线快照 | 全量 | 无 | 小 ✅ 已完成 |
| **P1** 双线合并 | B1 要素内 34 组 + B2 跨要素 4 组 + 擂鼓石大街 part1 修形 | 34+4 组 | P0 | 大 |
| **P2** 缺线补齐 | C 类 19 条（P2a 阻塞项 3 条 → P2b 其余 16 条） | 19 条 | P1 | 大 |
| **P3** 断口接续 | A 类 21 条（P0 实测，按断口长度分三档） | 21 条 | P1 | 中 |
| **P4** 示意线重标 | D 类 13 条按影像重描 | 13 条 | P1 | 大 |
| **P5** 收尾 | E 退化线补点、F 越界裁剪、H 新增字段、G 残余悬空 | 4+2+64+余量 | P1–P4 | 中 |

### P0 基线体检（前置，必须先做）

1. 运行 `audit.mjs`，把七类问题的**当前数量清单**写入 `reports/roads-audit-<日期>.json`。
2. 以 `git tag` 或分支打一个只读基线（例：`roads-baseline`）。
3. **判定门禁**：若某类实际数量与文档表格差异 >20%，先回写文档再动手，避免按过期清单改。

#### P0 执行结果（2026-10-24，已完成）

- 基线：`c8b0f45`，标签 `roads-baseline-20261024`
- 规模：**64 要素 / 130 段 / 5244 点**；`dataStatus` 为 `osm` 51 条、`estimated` 13 条
- 报告：`reports/roads-audit-20261024.json`（脚本：`scripts/roads/audit.mjs`，`--check` 可直接做 I-1/I-2/I-4 验收）
- 自检：`npm run validate:data` 通过（0 警告）

| 类别 | 清单值 | 实测值 | 结论 |
| --- | ---: | ---: | --- |
| A 线中断 | 11 | **21** | 文档漏计 10 条（多为 30–50m 的小断口，见下） |
| B1 要素内双线 | 13 | **34 组** | 文档表格本身就有 37 行，"13" 是"13 条路"被误当成组数 |
| B2 跨要素双线 | 3 | **4** | 多出 南湖大街↔五马街、南湖大街↔顺河街 两组 |
| C 缺线 | 19 | 19 | 一致 |
| D 示意线 | 13 | 13 | 一致 |
| E 两点退化线 | 4 | 4 | 一致 |
| F 坐标越界 | 2 | 2 | 一致 |
| G 端点悬空 | 48 | 48 | 一致 |

**P0 新增结论（后续批次据此调整）**

1. **A 类实际是 21 条**，文档 A1/A2/A3 合计只列了 13 条。实测断口最大 6 条为：温泉路 7840m、北上高大街 4166m、梳洗河 2883m、万官大街 2203m、环山东路 1359m、泮河大街 1246m；另有 长城路 28 簇/34m、东岳大街 15 簇/32m、环山路 10 簇/30m 等碎断口。
2. **温泉路、北上高大街、梳洗河、泮河大街** 的断口 >1km，文档未列，需在 P3 重新判断是漏绘还是同名不同段。
3. **B2 的 4 组** 中，五马街↔顺河街实测 **100% 重合、平均 16m、重合 6.98km**，比文档的 47% 严重得多，基本可确认是同一模板线画了两遍；南湖大街↔五马街（46%）、南湖大街↔顺河街（43%）说明这两条示意线还压到了真实的南湖大街上。
4. **环山路↔环山东路** 实测重合 79%、平均 19m、重合 4.84km，文档写的"平均 1m"偏小，但"判为副本、删其一"的结论不变。
5. 另有 4 条非 `estimated` 线顶点数 ≤7 且长度 >500m：佳苑路、仰圣街、虎山东路、康复路，疑似也是模板线，P4 一并复核。

**文档回写**：`路网数据补全清单-交付版.md` 属交付稿，本方案不改原文；以本节表格作为后续批次的执行口径。

### P1 双线合并（决定边界贴合度，优先级最高）

处理顺序：**先跨要素（B2），再要素内（B1）**，因为 B2 删错会影响 B1 的配对。

- **B2 四组**：环山路↔环山东路（重合 79%、平均 19m，判为副本，删环山东路要素）；北新街↔虎山东路、五马街↔顺河街（100% 重合，疑为同一模板线画两遍）、南湖大街↔五马街 / 南湖大街↔顺河街（43–46%，示意线压到真实道路上）。先按影像确认是否真是并行两条街，确认后再决定删/留。
- **B1 三十四组**（P0 实测，清单原表 37 行、"13 条路"非组数）：按"保留完整连续一侧、或取两线中点"合并；判定参数沿用文档：每 20m 采样、40m 邻域、平均间距 5–25m、重合占比 >30%。
- **特例**：擂鼓石大街 `part1` 首尾同点属于折返，按"裁到离起点最远点"修形；同批补 A1 中擂鼓石大街约 1000m 的东段断口。
- 产出：每删/并一条，`note` 写明 `merged-dual` 或 `single-side`；`centerlineMethod` 字段在 P5 统一补。

**验收**：I-2（40m 内并行且重合 >300m 判不通过）为零；要素数由 64 降到约 48–50。

### P2 缺线补齐（C 类）

- **P2a 阻塞项**：谢过城街（凤台—兴隆交界）、大众桥、下河桥。这 3 条未完成前，相关学区边界无法闭合。
- **P2b 其余 16 条**：白玉堂街、大官庄街、岱阳大街、法院街、韩家结庄村委西路、惠丰园西小路、金山东街、金山东巷、金山西街、三里北街、上高东路、盛和路、十五号路、堰东路、堰岭环路、迎暄大街、优山美地西邻路。
- 繁荣大街**不补**（文档已注明以北上高大街代表）。
- 新增线必须：端点落在既有道路的交点上（≤5m）、`sourceType` 与 `accuracyM` 如实填写，不得再生成模板直线。

**验收**：C 类 19 条逐条有要素；新增线与既有线无 40m 内、>300m 的重合。

### P3 断口接续（A 类）

分三档，档位不同处理方式不同：

P0 实测 A 类共 21 条，档位按本次实测断口长度重排（文档原表只列 13 条）：

| 档 | 对象（P0 实测） | 处理 |
| --- | --- | --- |
| A3 <30m | 长城路 34m、东岳大街 32m、环山路 30m 等碎断口簇 | `connect.mjs` 直接吸附，无人工判断 |
| A2 30–300m | 迎春路 243、泰山大街 119、岱宗大街 99、红门路 79、虎山路 48 等 | 吸附上限 300m，要求端点朝向与连接方向夹角 ≤90°，避免画出折返尖刺 |
| A1 >300m | 温泉路 7840、北上高大街 4166、梳洗河 2883、万官大街 2203、环山东路 1359、泮河大街 1246（均为 P0 新增，文档未列） | **必须人工/影像确认**：确认是漏绘则补中间段；确认是同名不同段则拆成两个要素并在 `note` 写原因 |

- 京沪铁路 1112m 断口已越界，**保留断开**，不接。
- G 类 48 条悬空端点与 A 类重合，统一走 `connect.mjs`，阈值 40m。

**验收**：I-1（同 name 多段且间距 <300m 视为不合格）、I-3（交叉口端点 ≤5m）。

### P4 示意线重标（D 类，质量瓶颈）

13 条：谢过城街、五马街、荣疗东路、顺河街、北新街、北新东街、迎春西路、唐訾路、博城路、致富路、荣军医院东路、唐王河、芝田河。

- 谢过城街先做（P2a 已补线，这里只做重标）。
- 用天地图影像逐条描线，**每 100–200m 一个顶点，交叉口必须有点**。
- 重标后 `dataStatus` 由 `estimated` 改为 `traced`，`accuracyM` 标 ≥50。
- 唐王河、芝田河是河流，`type` 保持 `河流`，不要混入道路样式。

**验收**：13 条均 ≥20 个顶点；与底图道路重合度目视无偏移；I-2 仍为零。

### P5 收尾

1. **E 类**：仰圣街、岱庙北街、梅山东路、泰山大桥补交叉口顶点（≥3 点）。
2. **F 类**：辛泰铁路（最远 117.5553，越界 90 点）、京沪铁路（6 点）裁剪到 `116.85–117.30 / 35.85–36.35`。
3. **H 类**：为 64 条统一补 `sourceType` / `accuracyM` / `centerlineMethod`，保留 `dataStatus`。
4. **G 类余量**：P3 之后仍悬空的，按 30m 阈值再吸附一轮；超阈值逐条记录。

## 3. 批次依赖与执行顺序

```
P0 体检 → P1 双线合并 → P3 断口接续 → P2 缺线补齐 → P4 示意线重标 → P5 收尾
                ↘（B2 跨要素判定）→ P2a 谢过城街
```

- P1 必须早于 P2/P3：双线未合并时补线，会与新线再撞出重复。
- P3 早于 P2：先把既有路网闭合，新线端点才有确定的交点可吸附。
- P4 可与 P2b/P3 并行（不同要素，互不重叠）。
- P5 必须在全部几何定稿后执行，字段补全才有意义。

## 4. 统一验收（每批都要跑）

对应文档 I 类 6 条，建议落在 `audit.mjs --check`：

| 编号 | 标准 | 实现方式 |
| --- | --- | --- |
| I-1 | 同 name 只允许 1 要素；多段间距 >300m 且说明原因 | 按 name 分组 + 端点聚类 |
| I-2 | 40m 内并行且重合 >300m 判不通过 | 20m 采样 + 邻域统计 |
| I-3 | 交叉口端点 ≤5m | 端点对最近距离 |
| I-4 | 坐标在 `116.85–117.30 / 35.85–36.35` | bbox 扫描 |
| I-5 | `npm run validate:data` 通过 | 直接调用 npm 脚本 |
| I-6 | 行尾 CRLF | 写入时统一 `.replace(/\r?\n/g, "\r\n")` |

每批结束的固定动作：`audit.mjs --check` → `npm run validate:data` → 提交（只提交 `data/roads.geojson`）。

## 5. 风险与回滚

- **误删风险（P1）**：跨要素重复判定容差只有 1m，先做 dry-run 输出配对清单，人工过一遍再 `--write`。
- **假线风险（P2/P4）**：严禁再生成 <10 顶点的模板直线；`audit.mjs` 对"顶点数 <10 且长度 >500m"的线直接报错。
- **越界回灌（F）**：裁剪后要确认没有把有效段一起裁掉，裁剪前后长度差 >5% 时提示人工确认。
- **回滚**：每批改动前 `git stash`/分支隔离；过程稿写 `reports/`（已被 `.gitignore` 忽略），不提交。
- **发布隔离**：全程不碰 `data/releases/2026.10.9/`，等全部批次验收通过后再单独走一次发布流程（`new-data-release.mjs` + `check-release.mjs`）。
