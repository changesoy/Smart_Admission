# 交点图谱构建脚本规划（L0）

> 状态：**规划稿，未实施**。当前路网仍需优化（21 条缺线源、13 条 `estimated` 待重标定），
> 此时插点会让 `roads.geojson` 的顶点编号与交点位置反复漂移，收益低、噪声大。
> 定位：[交接-路网与学区边界-2026-10-24.md](./交接-路网与学区边界-2026-10-24.md) 第四节 L0 层的落地细化。
> 本文件只形成规划：不修改业务代码、不新增依赖、不改动 `data/` 下任何文件。

## 一、目标与非目标

### 目标

1. **交点是路-路交点，不是独立概念**：一次算出 64 条线两两交点，供 L1 用"沿某路、从交点 A 到交点 B"描述四至段序列。
2. **拓扑可查**：每个交点带沿路里程 `s` 与顶点序号，L2 的"从 A 到 B 沿路切片"退化为里程区间裁剪，不再重新求交。
3. **拓扑可复现**：脚本幂等，重跑不改变输出字节；道路几何微调后重跑即可，无需人工维护交点表。
4. **缺口可见**：未相交、近邻、孤立道路、分段间隙都进覆盖率报告，作为"路网还需补哪些线"的依据。

### 非目标

- 不做四至文本自动解析（那是 L1，且包含"南关中学东界""优山美地西邻路"等非路名参照，必须人工指定节点）。
- 不做路径寻路算法（L2 的 DFS/最短路）。
- 不做几何修复：吸附只影响"节点登记"，不在本层横向挪动道路中心线。
- 不改 `zones.geojson`。

## 二、实测基线（2026-10-24，64 条路网）

探针脚本（`reports/probe-l0.mjs`、`reports/probe-l0-gaps.mjs`，均被 gitignore）实测：

| 指标 | 数值 |

| 最近距离 1–3 m | 5 对 |

| 最近距离 10–30 m / 30–60 m | 42 对 / 72 对 |
| 10 m 内无任何邻居的道路 | 12 条：泮河大街、荣疗东路、财源北街、唐訾路、博阳路、荣军医院东路、梳洗河、唐王河、芝田河、梅山东路、罗汉崖路、泰山大桥 |

## 三、核心设计决定

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D1 | **分级判定**：严格相交 + 端点/最近距离 ≤ 3 m 记 `node` 入库；3–10 m 仅记 `candidate` 进报告；> 10 m 忽略 | 3 m 能覆盖 13+5 个 T 形路口；3–10 m 多为实测偏差或真实不相接，机器无法裁定，交人工 |
| D2 | 容差参数化：`--tol 3`（吸附）、`--candidate 10`（报告上限），默认值写进报告头部 | 路网优化后口径可能调整，避免改代码 |
| D3 | **两阶段生成**：先求交（不改几何）→ 再插点 → 用插点后的最终几何回算 `s` 与 `vertex` 下标回填 | 否则 `s` 与写回文件不一致，L2 切片会错位 |
| D4 | `intersections.geojson` 是交点唯一事实来源；`roads.geojson` 只**插入顶点**，不横向挪线 | 保持 OSM 中心线不动；吸差点记录 `offsetM` 供 L2 判断 |
| D5 | **幂等**：目标位置 0.5 m 内已有顶点则复用，不重复插；输出按固定顺序序列化 | 允许"重抓 OSM → 重跑脚本"循环，重跑后文件字节不变 |
| D6 | 交点 id = `ix_<roadIdA>_<roadIdB>_<n>`，`roadId` 按 ASCII 升序，`n` 沿 A 起点里程递增；同时写人读 `label`（如"东岳大街×温泉路#2"）与坐标 | 可读、可排序、可作文本键；几何漂移后靠坐标复核，靠报告比对提示序号失效 |
| D7 | 多路共点按 **1 m 聚类**成一个节点，`members` 列出全部参与路 | 三岔/四岔路口必须是一个节点，否则 L2 寻路会在同一处出现 3 个孤立点 |
| D8 | 共线重叠（`den == 0` 且区间相交）只记 `kind: "overlap"` 报告，不插点、不自动改写 | 重叠段是"同一条线的双份几何"，插点无意义；处理方式要人工定（合并或删线） |
| D9 | `estimated` 参与的交点标 `confidence: "low"`；`osm`×`osm` 标 `high` | 示意线偏差数米到数十米，L1/L2 需要知道哪些节点可信 |
| D10 | 不引入几何依赖，自写段求交 + 100 m 网格分桶 | 5,114 段用网格分桶秒级完成；项目刻意零几何依赖 |

## 四、数据结构

### 4.1 `data/intersections.geojson`（新增，入库并纳入 `dataPaths`）

```jsonc
{
  "type": "FeatureCollection",
  "generatedAt": "2026-…",            // 顶层 foreign member，便于复核
  "source": { "roadsSha256": "sha256:…", "tolM": 3, "candidateM": 10 },
  "features": [
    {
      "type": "Feature",
      "geometry": { "type": "Point", "coordinates": [117.185267, 36.219728] },
      "properties": {
        "id": "ix_road_023_road_040_2",
        "label": "明堂路×环山东路#2",
        "kind": "cross",              // cross | touch | snap
        "confidence": "high",         // high | low（含 estimated 线为 low）
        "offsetM": 0.0,               // 吸附量；严格相交为 0
        "roads": [
          { "roadId": "road_023", "name": "明堂路", "part": 0, "vertex": 24, "s": 1532.44 },
          { "roadId": "road_040", "name": "环山东路", "part": 0, "vertex": 12, "s": 402.13 }
        ]
      }
    }
  ]
}
```

`s` = 沿该路（含所有 part 顺序累计）从起点到该点的米数；`vertex` = 插点后该顶点在该 part 坐标数组中的下标。
`kind` 口径：`cross` 严格穿过；`touch` 端点精确落在另一条线上（0 容差）；`snap` 最近距离 ≤ `tol`。

### 4.2 `roads.geojson` 的改动

- 只插入交点坐标，**原有顶点、顺序、`properties` 逐字节不变**。
- 插入坐标保留 7 位小数（≈1 cm），与现有坐标精度一致。
- 文件仍为 CRLF（`.gitattributes` 规定 `data/** text eol=crlf`）。
- 吸附点按各自路的垂足插入（不横向位移），因此两侧顶点可能相差 ≤ 3 m，`offsetM` 记录该差值。

## 五、算法

1. **加载**：读 `data/roads.geojson`；按 `roadId` 建索引，记 `estimated` 集合。
2. **投影**：等距圆柱投影到米制（以泰安纬度 36.2° 取 `kx = 111320·cos(lat)`），所有容差与距离在米制下计算。
3. **分桶**：100 m 网格，每段写入其 bbox 覆盖的全部格子。
4. **段对判定**（同 `roadId` 跳过）：
   - 严格相交 → `cross`，坐标取解析交点；
   - `den == 0` 且重叠区间非空 → `overlap`（报告用）；
   - 端点/最近距离 ≤ `tol` → `snap`，坐标取"一端投影 + 另一端投影"的中点，与两线距离写入 `offsetM`；
   - `tol < d ≤ candidate` → `candidate`（报告用，不入库）。
5. **聚类**：节点 1 m 内合并为一个 `cluster`，成员去重后写 `roads` 数组。
6. **插点**：对每个节点，在该路 `part` 的对应段内按参数 `t` 插入（`t≈0/1` 时复用端点）；已有顶点 0.5 m 内则复用。
7. **回填**：用插点后的几何重算 `vertex` 与 `s`，写 `intersections.geojson`。
8. **报告**：写 `reports/intersections/<YYYY-MM-DD>.json`，控制台打印摘要。

## 六、覆盖率报告内容

| 段落 | 内容 | 用途 |
| --- | --- | --- |
| `totals` | 节点数、`kind` 分布、`confidence` 分布、涉及路对数 | 一眼看规模 |
| `perPair` | 每个路对的交点数（含多点的 20 对） | 检查是否漏掉同名路多点 |
| `candidates` | 3–10 m 的 12 对：最近距离、最近点坐标、两条路名 | **人工裁定清单**，每条须有结论 |
| `isolatedRoads` | 10 m 内无邻居的 12 条 | 补线优先级依据 |
| `partGaps` | 7 条的分段间隙与缺口端点坐标 | L2 桥接依据 |
| `overlaps` | 共线重叠区间 | 双线问题清单 |
| `lowConfidence` | 含 `estimated` 的节点 | 这些节点的边界不可直接采用 |

## 十、推进顺序与验收

**顺序**（前两步完成后再动这一步）：

1. 路网优化收敛：21 条补线源的 1 条 OSM 命中优先、13 条 `estimated` 按影像重标定（交接文档待办 #6）。
2. 定 Q1–Q4。
3. `--write` 前先跑 dry-run，人工把 `candidates` 的 12 对全部裁定完毕。
4. 正式插点 → 发新版本 → 才进 L1（`zone_034` 四至段序列原型）。

**验收标准**：

- 64 条线中至少 52 条（80%）至少有一个节点；`isolatedRoads` 与上一版报告相比不再新增。
- 每个 `cross` 节点的坐标在两侧路的顶点数组中**精确存在**（7 位小数一致）。
- 连续执行两次 `--write`，`roads.geojson` 与 `intersections.geojson` 字节完全相同（幂等）。
- 报告里 `candidates` 每条都有 `promote` 或 `ignore` 结论。
