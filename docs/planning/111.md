## 一、任务 [1] `server/` FastAPI Backend Lite

### 【目标】

建立最小的服务端边界：只承担「需要服务器能力」的三件事，不做任何业务计算。

### 【目录结构】

```text
server/
├─ app.py              # FastAPI 实例、路由注册、统一异常处理
├─ config.py           # 环境变量读取与校验（含 searchBounds）
├─ routes/
│  ├─ __init__.py
│  ├─ health.py        # GET /api/health
│  ├─ version.py       # GET /api/version
│  └─ search.py        # GET /api/search
├─ services/
│  ├─ __init__.py
│  └─ tianditu.py      # 天地图 Search 调用封装（timeout / 缓存 / 错误归一）
└─ requirements.txt

.env.example           # 仓库根目录
```

### 【接口契约】

**`GET /api/health`**

```json
{
  "ok": true,
  "status": "healthy",
  "uptimeSeconds": 1234,
  "dataVersion": "2026.09.1"
}
```

**`GET /api/version`**

```json
{
  "ok": true,
  "appVersion": "1.0.0",
  "buildTime": "2026-09-20T10:00:00Z",
  "dataVersion": "2026.09.1",
  "dataGeneratedAt": "2026-09-20T09:00:00Z",
  "dataEffectiveYear": 2025
}
```

- `appVersion` 来源：环境变量 `APP_VERSION`（未设置时回退 `package.json` 的 `version`）；
- `buildTime` 来源：环境变量 `BUILD_TIME`（未设置时返回 `null`，不伪造）；
- `dataVersion` 等来源：读取 `DATA_DIR/current.json` + `DATA_DIR/releases/<version>/manifest.json`；
- 读不到数据版本时**不报 500**，返回 `dataVersion: null` 并在 `ok: true` 中如实反映，避免「健康检查把整个站点判死」。

**`GET /api/search?q=<关键词>&count=<1-20>`**

成功：

```json
{
  "ok": true,
  "query": "泰安望岳中学",
  "count": 2,
  "cached": false,
  "bounds": {
    "minLng": 116.85,
    "maxLng": 117.3,
    "minLat": 35.85,
    "maxLat": 36.35
  },
  "results": [
    {
      "uid": "...",
      "name": "...",
      "address": "...",
      "lng": 117.12,
      "lat": 36.19
    }
  ]
}
```

失败（**统一结构，所有错误共用**）：

```json
{
  "ok": false,
  "error": { "code": "UPSTREAM_TIMEOUT", "message": "上游搜索服务超时" }
}
```

| HTTP | code               | 触发条件                                 |
| ---- | ------------------ | ---------------------------------------- |
| 400  | `BAD_REQUEST`      | `q` 为空 / 超长（> 50 字）/ `count` 非法 |
| 429  | `RATE_LIMITED`     | 超出限流                                 |
| 502  | `UPSTREAM_ERROR`   | 上游返回非 2xx 或 JSON 无法解析          |
| 503  | `TOKEN_MISSING`    | 未配置 `TIANDITU_SEARCH_TK`              |
| 504  | `UPSTREAM_TIMEOUT` | 上游超时                                 |

### 【环境变量与 `.env.example`】

```dotenv
# 服务端天地图搜索 token（与前端瓦片 token 分离，不要复用）
TIANDITU_SEARCH_TK=

# 数据目录（开发为 ./data，生产为 /workspace/data）
DATA_DIR=./data

# 应用版本与构建时间（生产构建时注入；开发留空）
APP_VERSION=
BUILD_TIME=

# 搜索代理调优
SEARCH_TIMEOUT_SECONDS=5
SEARCH_CACHE_TTL_SECONDS=60
SEARCH_RATE_LIMIT_PER_MINUTE=30
```

- `.env` 必须加入 [.gitignore](file:///d:/Projects/VSCode/Smart_Admission/.gitignore)（当前未包含）；
- `.env.example` 只放键名与空值，**不写任何真实 token**。

### 【实现要点】

- token 只从环境变量读取，**代码与仓库中不出现任何 token 字面量**；
- 上游调用用 `httpx.AsyncClient`，显式 timeout；上游非 2xx、异常 JSON、空响应统一归一为上面的错误结构；
- 短时缓存：`q + count` 为键的内存 TTL 缓存（TTL 60s），命中时 `cached: true`；
- 简单限流：按客户端 IP 的每分钟计数（进程内即可，不引入 Redis）；
- 复用范围过滤：服务端保留一份 `searchBounds`（与 [config.js](file:///d:/Projects/VSCode/Smart_Admission/js/config.js#L96-L102) 保持一致），越界结果不进 `results`；
- 查询沿用 `泰安市<q>` 前缀，避免拿到外地同名 POI；
- 不做 CORS：前端与 API 同源，**不要**为了「方便」开 `allow_origins=["*"]`。

### 【明确不做（守住 Backend Lite 边界）】

- 不做 Turf 点面判断、学区查询、返回学校/政策数据；
- 不做账号、JWT、管理后台；
- 不把 JSON 导入 SQLite；
- 不做地图瓦片代理；
- 不做 `POST /api/feedback`（属 P2-2，可砍）。

### 【依赖】

```text
# server/requirements.txt —— 版本号以首次安装时实际锁定为准，不使用范围符号
fastapi==<锁定版本>
uvicorn[standard]==<锁定版本>
httpx==<锁定版本>
python-dotenv==<锁定版本>   # 仅用于本地 dev 读取 .env
```

- 技术选型沿用上游规划的 FastAPI；
- 前端仍用 npm，服务端用 pip/venv，**两套工具链各自独立，不混用、不互相生成 lockfile**；
- 新增依赖的理由：`fastapi` 提供路由与校验，`uvicorn` 为 ASGI 服务器，`httpx` 为异步上游客户端（均无法用标准库简洁替代）；
- 安装后通过 `pip freeze` 锁定实际版本写回 `requirements.txt`。

### 【文件清单】

| 操作     | 文件                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 新增     | `server/app.py`、`server/config.py`、`server/routes/*.py`、`server/services/*.py`、`server/requirements.txt`、`.env.example` |
| 修改     | `.gitignore`（增加 `.env`、`.venv/` 已有则确认、`storage/`）                                                                 |
| **不改** | `js/**`、`index.html`、`css/**`、`data/**`                                                                                   |

### 【验收】

- `uvicorn server.app:app --reload` 可启动，无未捕获异常；
- `curl /api/health` → 200，字段齐全；
- `curl /api/version` → 200，`appVersion` 与 `package.json` 一致；数据版本缺失时 `dataVersion: null` 且不 5xx；

## 二、任务 [3] 数据版本体系

### 【目标】

把「直接读 `./data/*.json`」改造成「先读指针、再按版本整包读取」，使数据可整体切换与回滚，并让运行中的会话不可能混用两个版本。

### 【目标目录】

```text
data/
├─ current.json                 # 只指向当前版本，不含数据
└─ releases/
   └─ 2026.09.1/
      ├─ manifest.json
      ├─ zones.geojson
      ├─ schools.json
      ├─ policies.json
      ├─ faq.json
      ├─ contacts.json
      ├─ policy_diff.json
      ├─ address_points.json
      ├─ keywords_index.json
      ├─ zones_history.json
      ├─ rumors.json
      └─ simulator_rules.json
```

`current.json`：

```json
{ "version": "2026.09.1" }
```

`manifest.json`：

```json
{
  "version": "2026.09.1",
  "generatedAt": "2026-09-20T09:00:00Z",
  "effectiveYear": 2025,
  "appVersionRange": ">=1.0.0",
  "files": [
    { "name": "zones.geojson", "sha256": "...", "bytes": 12345 },
    { "name": "schools.json", "sha256": "...", "bytes": 6789 }
  ]
}
```

### 【前端改造】

**[config.js](file:///d:/Projects/VSCode/Smart_Admission/js/config.js#L38-L50) 的 `dataPaths` 语义从「路径」改为「文件名」**，并新增版本入口配置：

```js
  /** 数据版本入口:先读指针,再按版本目录整包加载 */
  dataRelease: {
    currentPointer: "./data/current.json",
    releasesDir: "./data/releases",
  },

  /** 数据文件名映射,实际路径由 dataRelease 解析后拼接 */
  dataPaths: {
    zones: "zones.geojson",
    schools: "schools.json",
    // ... 其余保持同名
  },
```

**[dataService.js](file:///d:/Projects/VSCode/Smart_Admission/js/dataService.js#L49-L85) 增加版本解析阶段**，`loadAllData()` 流程变为：

1. `fetch(currentPointer)` → 取 `version`（失败即视为核心失败，因为无版本无法定位数据）；
2. 拼出 `base = ${releasesDir}/${version}/`；
3. 之后的核心/可选数据加载逻辑**保持不变**，仅路径改为 `base + dataPaths[key]`（现有并行加载与降级策略不动）；
4. `loadAllData()` 返回值增加 `dataVersion`，供页面展示与后续与 `/api/version` 比对；
5. 版本在整个会话内只解析一次并缓存，**不允许中途重新解析**（防止一次会话混用两版本）。

**构建配置**：[vite.config.js](file:///d:/Projects/VSCode/Smart_Admission/vite.config.js#L14-L23) 的 `cpSync(..., { recursive: true })` 已能复制 `releases/` 子目录与 `current.json`，无需改动；但需在验收中确认 `dist/data/releases/2026.09.1/` 确实存在。

### 【版本包生成方式】

本次的快照内容是**原样复制现有 `data/*.json`**，不修改任何数据内容（占位数据随快照进入 release，由第 5 步清理后另出 `2026.10.1`）。

建议附带一个生成脚本 `scripts/new-data-release.mjs`：

- 入参：版本号；
- 行为：复制 `data/` 下约定的数据文件到 `data/releases/<版本>/`，计算 `sha256` 与 `bytes` 生成 `manifest.json`；
- **不自动修改 `current.json`**（切换版本必须是显式动作，便于回滚与审阅）。

> 若不写该脚本，则手工生成 manifest 的 `sha256`；但手工方式难以保证发布一致性，建议保留脚本。

### 【文件清单】

| 操作 | 文件                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------- |
| 新增 | `data/current.json`、`data/releases/2026.09.1/**`、`scripts/new-data-release.mjs`（建议）                |
| 修改 | `js/config.js`（`dataPaths` 语义 + `dataRelease`）、`js/dataService.js`（版本解析 + 返回 `dataVersion`） |
| 保留 | 原 `data/*.json` 暂不删除，作为下一版本的编辑源（迁移期双轨，避免一步不可运行）                          |

### 【验收】

- 页面正常加载，功能无回归（地址搜索、地图点击、双学段结果、政策、自查均正常）；
- 浏览器 Network 中，数据请求路径均为 `./data/releases/2026.09.1/*`，且 `current.json` 只请求一次；
- 控制台无新增 JS 异常；
- `npm run build` 后 `dist/data/` 内含 `current.json` 与 `releases/2026.09.1/` 全部文件；
- **回滚演练**：把 `current.json` 的 version 改成一个存在的旧版本（可先复制一份 `2026.09.0`）→ 页面整体切到旧数据，无需改任何代码；
- 把 `current.json` 指向不存在的版本 → 页面给出明确加载失败提示，而不是静默空白。

### 【注意（本轮不解决的问题）】

- `manifest.effectiveYear` 与数据内容不一致：`zones.geojson` 全部为 `year: 2025`，而 `policies.json` 为 2026。本轮**如实记录**当前状态，不做粉饰；
- 现有 `data/*.json` 与 `releases/` 内容的**双轨期**是刻意设计，第 5 步清理完成后由 `2026.10.1` 收敛。

## 三、任务 [4] `npm run check:release`

### 【目标】

把「靠人记得检查占位数据」变成「一条命令必然拦住」，并与开发期校验分离。

### 【结构建议（避免复制糊墙皮）】

[validate-data.mjs](file:///d:/Projects/VSCode/Smart_Admission/scripts/validate-data.mjs) 里已有 ID 唯一性、引用完整性、Polygon 闭合、坐标范围等逻辑。**不要把这些逻辑再抄一份到 check-release**，而是抽公共模块：

```text
scripts/
├─ lib/
│  └─ validate-core.mjs      # 抽出的公共校验:结构/ID/引用/几何/坐标
├─ validate-data.mjs         # 开发期:允许 pending / estimated,只查结构合法
└─ check-release.mjs         # 发布期:validate-core + 发布专属严格检查
```

`validate-core.mjs` 导出形如 `validate(dataset, { strict })` 的函数，两个入口共用；`strict` 控制是否启用发布专属规则。

### 【`check-release.mjs` 校验项】

**A. 拒发类（必须失败）**

- placeholder 黑名单命中（扫描 release 目录下**全部**数据文件）：
  `example.gov.cn`、`待补`、`TODO`、`示例电话`、`000000`、`XXXXXXXX`、`fake`、`mock`；
- manifest 缺失，或缺少 `version` / `generatedAt` / `effectiveYear` / `files`；
- `manifest.version` 与所在目录名不一致；
- `manifest.files` 与实际目录文件不一致（缺失或多余）；
- 文件 `sha256` 与 manifest 记录不符；
- `current.json` 指向的版本目录不存在；
- 引用完整性错误（zoneId → schoolId → policyId、school → policy、自查规则 → materials / policyIds）；
- 重复 ID；
- Polygon 首尾未闭合；
- 坐标越界。

**B. 提示类（不失败，但打印）**

- `dataStatus: estimated`、`geometryAccuracy: manualApproximation` 的条目数量与清单；
- 各文件年份分布（用于暴露 2025/2026 混用）；
- 未被任何数据引用的孤立 schoolId / policyId。

### 【package.json】

```json
"scripts": {
  "check:release": "node scripts/check-release.mjs"
}
```

- **不并入 `check`**：上游明确要求「开发检查与发布检查分离」，`check` 保持 `lint + validate:data`；
- 退出码：存在拒发项 → `exit 1`；仅提示项 → `exit 0`。

### 【验收】

- 对当前 `releases/2026.09.1` 运行 → 明确列出所有 `【待补…】` 命中位置（**预期结果为失败**），错误信息含文件名与字段/条目定位；
- 故意改坏 `manifest.version` → 失败并指出目录名不匹配；
- 故意手工改动某个数据文件一个字节 → `sha256` 校验失败；
- 故意造重复 `zoneId`、删掉一个被引用的 `schoolId`、把 Polygon 首尾点改不闭合 → 各自失败；
- 删除 `current.json` 指向的目录 → 失败；
- 干净数据（可用 `2026.09.0` 构造测试用假数据）→ `exit 0`，仅打印 estimated 提示；
- `validate-data.mjs` 行为不变，`npm run check` 仍通过。

## 四、执行顺序与工时

顺序：**1 → 3 → 4**

- 1 与 3、4 无耦合，可先做（独立可验证）；
- 3 必须先于 4：4 的 manifest / 版本一致性 / sha256 检查依赖 3 产出的目录结构；
- 4 收敛时需回头确认：`validate-data.mjs` 与 `check-release.mjs` 确实共用 `validate-core.mjs`，无重复逻辑。

| 任务                                                        | 估算     | 依赖 |
| ----------------------------------------------------------- | -------- | ---- |

## 六、风险与应对

| 风险                                                         | 影响                 | 应对                                                                           |
| ------------------------------------------------------------ | -------------------- | ------------------------------------------------------------------------------ |
| 数据版本改造导致页面加载失败                                 | 核心功能回归         | `data/*.json` 保留双轨；版本解析失败给明确提示；改完立即跑一次全流程手工 smoke |
| `/api/search` 交付后长期无人调用，接线时才发现契约不合       | 返工                 | 本批次用 curl 固化契约样例；第 2 步严格按本节契约实现，不改字段名              |
| 服务端与前端 `searchBounds` 各写一份而漂移                   | 结果范围判定不一致   | 两处注释互相指向；第 2 步收敛时再次核对                                        |
| 抽 `validate-core.mjs` 时改动现有校验行为                    | `npm run check` 回归 | 抽取后先对比新旧脚本对同一数据的输出，确认无差异再合入                         |
| 新增 Python 依赖引入版本漂移                                 | 环境不可复现         | `requirements.txt` 全部固定版本；不混用包管理器；不使用范围符号                |
| `check:release` 因现存占位数据长期失败，被误判为「脚本坏了」 | 门禁被绕过           | 本文件与 docs/development.md 明确写出「预期失败 + 原因 + 由第 5 步消除」       |
