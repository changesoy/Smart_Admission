# 地图点选式学区边界工具实施方案

> 状态：已确认方向，交由角色 C 实现
>
> 目标：在标准化边界网络上通过点选、共边复用和受控候选路径生成学区草稿，降低后续新增或调整学区的人工录入成本
>
> 非目标：不自动解释官方四至，不替代人工裁定，不直接写正式发布数据

---

## 一、方案结论

工具采用“边界拼图”模式：道路、河流、铁路等要素经过交点计算和节点切分后形成稳定 `edgeId`；用户在地图上选择这些边，工具实时检查连续性、闭合和共边关系，最终导出只包含 `edgeRefs` 的学区草稿。

```text
boundary_features
        ↓ 自动计算交点、人工确认非连通交叉
network_nodes
        ↓ 按节点切分
network_edges
        ↓ 地图点选 / 共边复用 / 候选路径
zone_draft
        ↓ 自动校验 + 人工审核
zone_specs
        ↓ 确定性派生
zones.geojson
```

该工具有长期价值：网络只需标准化一次，后续新增学区主要变成选择既有边；相邻学区可以直接复用同一 `edgeId`，避免重复画线和坐标漂移。

## 二、技术边界

### 2.1 输入

- `boundary_features.v2.geojson`：只用于显示权威线几何；
- `network_nodes.json`：显示节点与连通状态；
- `network_edges.json`：唯一可选择对象；
- `zone_specs.v2.json`：显示已有学区和边占用情况；
- `zones.geojson`：只作为新旧边界对比图层。

### 2.2 输出

工具只导出 `zone_draft` JSON，不直接写入仓库数据：

```json
{
  "draftId": "draft_zone_006_20261117_01",
  "schemaVersion": 1,
  "zoneId": "zone_006",
  "boundaryText": "官方四至原文",
  "status": "readyForReview",
  "createdBy": "用户",
  "createdAt": "2026-11-17",
  "updatedAt": "2026-11-17",
  "rings": [
    {
      "role": "outer",
      "appliesToRingId": null,
      "steps": [
        {
          "stepId": "zs_0000009",
          "edgeRefs": [{ "edgeId": "be_0000001", "direction": "forward" }]
        }
      ]
    }
  ],
  "operations": [],
  "rejectReason": null
}
```

字段级冻结、状态取值与校验清单以 `docs/planning/草稿字段冻结清单.md` 为准；草稿按正式步骤绑定，`stepId` 沿用 `zone_specs.v2.json`，环级边序列由步骤拼接派生。

正式导入由独立 CLI 完成：

```text
zone_draft → validate-zone-draft → 人工确认 → import-zone-draft → zone_specs.v2.json
```

### 2.3 禁止事项

- 不保存自由坐标；
- 不直接修改边界要素、节点、边和正式学区文件；
- 不自动补画直线；
- 不在无解时选择最近道路；
- 不在多解时静默选择最短路径；
- 不允许选择 `retired`、`deprecated` 或 `boundaryEligible=false` 的边；
- 不把几何相交自动视为拓扑连通。

## 三、核心交互

### 3.1 地图显示

- 默认显示标准化边界要素，拓扑边以可点击线段叠加；
- 鼠标悬停显示 `edgeId`、要素名称、起止节点、核验状态和已占用学区；
- 已选边、候选边、共用边、不可用边和断点使用不同颜色；
- 可切换当前发布学区、新草稿和相邻学区图层；
- 可按名称、`featureId`、`nodeId`、`edgeId` 搜索定位。

### 3.2 选择边

- 点击边加入当前环，再次点击取消；
- 系统根据上一个边的终点判断方向；
- 非连续边不得直接加入，应提示当前断点和候选连接路径；
- 支持撤销、重做、清空当前环；
- 每次操作写入 `operations`，包含操作人、时间和关联原文片段。

### 3.3 自动补全

自动补全只缩短操作，不作业务决定：

1. 用户选择当前终点和目标节点；
2. 系统在 active、可作边界的拓扑边上寻找候选路径；
3. 零条候选时明确报无解；
4. 一条候选时预览，仍需用户确认；
5. 多条候选时全部列出并显示差异，禁止默认采用第一条；
6. 确认后才写入草稿。

### 3.4 边界拼图复用

系统维护派生索引：

```json
{
  "be_0000001": [
    { "zoneId": "zone_006", "ringRole": "outer", "direction": "forward" }
  ]
}
```

- 已被其他学区采用的边显示其学区名称；
- 新学区沿相邻学区边界时可一键选择连续共边；
- 同一边可反向使用；
- 工具提示共边复用，但不得自动修改相邻学区；
- 导入器必须验证共边坐标完全一致或完全反向。

### 3.5 排除区域

排除区域先判定几何形态，再决定写哪种环（契约 9.6）：

- 与外环相接、无法独立闭包的，按**凹口**并入外环，该段 `side=排除`，不建洞环；
- 完全内嵌、自成闭包的，才建 `role: hole` 的洞环，`appliesToRingId` 指向本学区外环；
- 完全在外、与主区不连通的飞地，进入裁定流程，不塞进洞环；
- 外环与洞环分别编辑；洞环必须独立闭合、位于外环内部，且只能由 `edgeRefs` 组成；
- 工具只能提示判定结果，最终形态由用户确认；
- 无现成网络边可表达的排除区域必须提交数据缺口或人工裁定，不允许自由切割 Polygon。

## 四、实现阶段

### 阶段 1：静态交互原型

- 使用现有 Leaflet，不新增地图框架；
- 读取 mock 节点与边；
- 完成边高亮、点选、取消、撤销、方向显示；
- 只在本地工具页运行，不接生产页面。

验收：能在 mock 网络上选择一个闭合环并导出稳定 JSON。

### 阶段 2：真实网络接入

- 接入 `network_nodes.json` 和 `network_edges.json`；
- 接入名称搜索、边状态和边占用索引；
- 大数据量下使用 Leaflet 图层分组或 Canvas 渲染；
- 不合格边必须不可选且可说明原因。

验收：真实网络可流畅点选，不因图层显示状态影响数据判断。

### 阶段 3：候选路径与共边复用

- 实现节点图上的候选路径搜索；
- 限制最大候选数量和搜索范围；
- 展示路径长度、经过要素和已占用学区；
- 实现连续共边的一键选择。

验收：无解、多解和唯一解三类 fixture 均有自动测试，任何情况都不静默决策。

### 阶段 4：草稿、校验和导入

- 实现草稿导入导出；
- 实现外环、洞环和操作记录；
- 开发只读 `validate-zone-draft`；
- 开发需显式确认的 `import-zone-draft`；
- 生成派生环、新旧差异报告和受影响学区清单。

验收：编辑器不能直接写正式文件；非法引用、断链、自交、未闭合和无裁定冲突均拒绝导入。

### 阶段 5：现有学区试用

- 先用 `zone_006`、`zone_031` 验证已有裁定；
- 再选一个含洞环或排除区域的学区验证 `hole`；
- 人工比较旧环、新环、官方原文和相邻学区；
- 修正交互问题后再扩展到全部学区。

## 六、验收标准

- 任意已选线段均可追溯到唯一 active `edgeId`；
- 导出的草稿不含经纬度坐标；
- 相邻边按 `nodeId` 精确连续；
- 外环和洞环闭合误差为 0；
- 多解、无解、断链和不可用边均显式阻断；
- 同一输入和操作序列导出字节一致；
- 撤销、重做不会改变未涉及的边；
- 编辑器刷新后可重新导入草稿并恢复状态；
- 编辑器无法直接改写正式数据；
- 通过草稿生成的派生环可以被现有前端读取；
- 现有学区、新草稿和共边归属在地图上可区分；
- 关键逻辑有 Node 自动测试，不依赖浏览器人工测试才能发现错误。

---

## 七、风险与止损

- **路网质量不足**：编辑器只暴露缺口，不允许局部补线；退回 A 修复；
- **几何相交误判连通**：由节点数据明确连接关系，编辑器不自行判断；
- **弱模型静默兜底**：所有失败条件写成测试和验收命令，禁止 `catch` 后继续；
- **编辑器范围膨胀**：首版只做点选、闭合、导出，不做大模型解析和在线协作；
- **性能问题**：先按地图视野加载边，必要时再引入空间索引，不提前增加依赖；
- **业务判断错误**：工具只提交草稿，最终采用始终由角色 B 人工确认。

若阶段 1 无法在 mock 网络稳定导出闭合草稿，应停止后续开发，先修正交互与数据模型，不继续叠加自动寻路。
